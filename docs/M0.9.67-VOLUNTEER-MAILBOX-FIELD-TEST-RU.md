# M0.9.67: field test volunteer mailbox

Статус: debug kit и fail-closed evidence verifier готовы. Сам сетевой прогон
должен выполняться отдельно, когда доступны Alice и Bob.

## 1. Что доказывает прогон

Сценарий проверяет, что Alice при выключенном Bob получает две независимые
store-signed квитанции, после чего runtime Alice останавливается. Затем Bob
забирает обе E2EE-реплики непосредственно у volunteer-процессов через Iroh,
добавляет событие в локальную историю до DELETE, получает подписанные delete
receipts и после restart не видит сообщение повторно.

Два volunteer-процесса можно держать на компьютере Alice. У них должны быть
разные state, Account Root, Iroh endpoint и store key. Это доказывает механизм
и transport/store diversity, но **не** независимость операторов или физических
машин.

На данном этапе существующий HTTPS mailbox ещё используется как compatibility
fallback и должен быть настроен в уже активном Alice/Bob mailbox binding.
Прогон отдельно доказывает Iroh PUT/LIST/DELETE реплик, но ещё не доказывает
полностью server-free offline delivery.

## 2. Подготовка

Kit создаётся из clean commit обычной debug-сборкой, без ZIP и release:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\new-kilogram-m0967-volunteer-field-kit.ps1
```

Скопируйте полученную папку на Bob либо положите её в общую синхронизируемую
папку. В kit находятся только стабильный `bin\kilogram-cli.exe`, публичная
документация и скрипты. Не копируйте туда state, runtime profile, IPC descriptor,
Account Root или seed.

Нужны уже связанные Alice и Bob со следующими состояниями:

- current Root-signed device lists и контакт друг с другом;
- общий private-chat conversation label;
- active mailbox capability Alice → Bob;
- локальные runtime profile и IPC descriptor вне общей папки;
- доступный HTTPS compatibility mailbox из этого binding.

Создайте новую пустую evidence-папку для каждого прогона. Скопируйте в неё
`manifest.example.json` как `manifest.json` и заполните `run_id`, Account IDs и
уникальный `message_marker`. `build_commit` не меняйте.

На каждом компьютере скопируйте соответствующий `*.local.example.psd1` в
приватную локальную папку, уберите `.example` и исправьте три пути. Config также
не должен находиться в kit/evidence.

В примерах ниже:

```powershell
$Kit = 'C:\Kilogram\kilogram-m0967-COMMIT-TIME'
$Evidence = 'C:\Kilogram\m0967-evidence-RUN'
$AliceConfig = 'C:\Kilogram\private\alice.local.psd1'
$BobConfig = 'C:\Kilogram\private\bob.local.psd1'
$Cli = "$Kit\bin\kilogram-cli.exe"
$Scripts = "$Kit\scripts"
```

## 3. Phase 01 — два volunteer provider

На одном постоянно включённом тестовом хосте один раз создайте два независимых
приватных профиля. Папки должны быть новыми:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\new-kilogram-volunteer-field-provider.ps1" `
  -ProviderName provider1 `
  -PrivateDirectory 'C:\Kilogram\private\m0967-provider1' `
  -CliPath $Cli

powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\new-kilogram-volunteer-field-provider.ps1" `
  -ProviderName provider2 `
  -PrivateDirectory 'C:\Kilogram\private\m0967-provider2' `
  -CliPath $Cli
```

Откройте два отдельных окна PowerShell и запустите процессы. Они остаются
foreground до `Ctrl+C`:

```powershell
$P1 = Import-PowerShellDataFile 'C:\Kilogram\private\m0967-provider1\provider1.local.psd1'
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\invoke-kilogram-volunteer-field-runtime.ps1" `
  -Role provider1 -Phase 01 -ProfileFile $P1.ProfileFile `
  -EvidenceDirectory $Evidence -CliPath $Cli
```

```powershell
$P2 = Import-PowerShellDataFile 'C:\Kilogram\private\m0967-provider2\provider2.local.psd1'
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\invoke-kilogram-volunteer-field-runtime.ps1" `
  -Role provider2 -Phase 01 -ProfileFile $P2.ProfileFile `
  -EvidenceDirectory $Evidence -CliPath $Cli
```

Когда в обоих логах появилась строка `status=runtime-listening`, из третьего
окна экспортируйте последние свежие offers:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$Scripts\export-kilogram-volunteer-field-offer.ps1" -ProviderName provider1 -EvidenceDirectory $Evidence
powershell -NoProfile -ExecutionPolicy Bypass -File "$Scripts\export-kilogram-volunteer-field-offer.ps1" -ProviderName provider2 -EvidenceDirectory $Evidence
```

Offers действуют 15 минут. Phases 02–04 нужно завершить в этом окне. При
истечении срока начните новый run/evidence directory; старые evidence-файлы не
перезаписываются.

## 4. Phase 02 — Alice и Bob импортируют одинаковых providers

Запустите Alice и Bob в отдельных окнах с phase `02-prepare`:

```powershell
$Alice = Import-PowerShellDataFile $AliceConfig
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\invoke-kilogram-volunteer-field-runtime.ps1" `
  -Role alice -Phase 02-prepare -ProfileFile $Alice.ProfileFile `
  -EvidenceDirectory $Evidence -CliPath $Cli
```

```powershell
$Bob = Import-PowerShellDataFile $BobConfig
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\invoke-kilogram-volunteer-field-runtime.ps1" `
  -Role bob -Phase 02-prepare -ProfileFile $Bob.ProfileFile `
  -EvidenceDirectory $Evidence -CliPath $Cli
```

После появления обоих IPC descriptors выполните на каждом хосте:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\import-kilogram-volunteer-field-providers.ps1" `
  -Role alice -IpcFile $Alice.IpcFile -EvidenceDirectory $Evidence -CliPath $Cli
```

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\import-kilogram-volunteer-field-providers.ps1" `
  -Role bob -IpcFile $Bob.IpcFile -EvidenceDirectory $Evidence -CliPath $Cli
```

Остановите Alice и Bob через `Ctrl+C`. Оба provider оставьте работать.

## 5. Phase 03 — Bob offline, Alice отправляет

Bob не запускайте. Снова запустите только Alice:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\invoke-kilogram-volunteer-field-runtime.ps1" `
  -Role alice -Phase 03-send -ProfileFile $Alice.ProfileFile `
  -EvidenceDirectory $Evidence -CliPath $Cli
```

В другом окне Alice поставьте ровно одно тестовое сообщение в очередь:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\queue-kilogram-volunteer-field-message.ps1" `
  -IpcFile $Alice.IpcFile -EvidenceDirectory $Evidence -CliPath $Cli
```

Дождитесь в Alice log одновременно:

```text
runtime_outbound_status=mailbox-stored
runtime_mailbox_replication_receipts=2/2
runtime_mailbox_replication_status=satisfied
```

Остановите Alice через `Ctrl+C`, затем зафиксируйте недоступность её IPC:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\confirm-kilogram-volunteer-field-sender-offline.ps1" `
  -IpcFile $Alice.IpcFile -EvidenceDirectory $Evidence -CliPath $Cli
```

## 6. Phase 04 — Bob получает только при остановленном Alice runtime

Provider процессы продолжают работать, Alice runtime не запускайте. Запустите
Bob:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\invoke-kilogram-volunteer-field-runtime.ps1" `
  -Role bob -Phase 04-receive -ProfileFile $Bob.ProfileFile `
  -EvidenceDirectory $Evidence -CliPath $Cli
```

Перед остановкой Bob дождитесь двух наборов строк с разными store keys:

```text
runtime_mailbox_replica_source_store_key=...
runtime_mailbox_replica_delete_status=deleted-after-commit
runtime_mailbox_inbound_source=volunteer-iroh
```

После двух реплик остановите Bob через `Ctrl+C`.

## 7. Phase 05 — restart и история

Ещё раз запустите Bob, дождитесь `status=runtime-listening`, оставьте его на
15–20 секунд и остановите. Повторной строки
`runtime_mailbox_inbound_source=volunteer-iroh` быть не должно:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\invoke-kilogram-volunteer-field-runtime.ps1" `
  -Role bob -Phase 05-restart -ProfileFile $Bob.ProfileFile `
  -EvidenceDirectory $Evidence -CliPath $Cli
```

После остановки runtime снимите локальную историю:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\capture-kilogram-volunteer-field-history.ps1" `
  -StateDirectory $Bob.StateDirectory -EvidenceDirectory $Evidence -CliPath $Cli
```

Теперь можно остановить оба provider-процесса.

## 8. Phase 06 — fail-closed проверка

Скопируйте неизменный precomputed boundary log из kit:

```powershell
Copy-Item -LiteralPath "$Kit\BOUNDARIES.log" -Destination "$Evidence\06-boundaries.log"
```

Запустите verifier:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$Scripts\verify-kilogram-volunteer-field-evidence.ps1" `
  -EvidenceDirectory $Evidence
```

Успех заканчивается `result : verified`. Проверка требует exact два distinct
store key/transport identity, обе sender receipts, остановленный Alice IPC до
получения, два Bob Iroh commits/deletes, отсутствие повторной volunteer-доставки
после restart и ровно одно вхождение уникального marker в истории.

## 9. Что не класть в evidence

Запрещено копировать seed, Account Root, `device-secret.key`, vault key, state
directory, runtime profile и IPC descriptor. Provider offer, store key,
transport identity, тестовый message marker и ограниченные runtime logs являются
публичными test artifacts. Если в тестовом сообщении были реальные данные,
такой evidence нельзя публиковать.
