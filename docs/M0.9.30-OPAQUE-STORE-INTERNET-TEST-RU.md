# M0.9.30: проверка opaque ticket store через интернет

Эта процедура проверяет обновление connection ticket между двумя уже
добавленными контактами через самостоятельно запущенный HTTPS-сервис. Она не
создаёт первый контакт и не проверяет анонимность.

## 1. Что потребуется

- сервер или VPS с публичным доменом и действующим HTTPS-сертификатом;
- reverse proxy, завершающий TLS;
- `kilogram-ticket-store` на том же сервере;
- Alice и Bob с уже проверенными runtime contacts и приватными IPC descriptor;
- точные Account ID друг друга и общий conversation label.

Порт самого store нельзя публиковать наружу: бинарник намеренно принимает только
loopback address.

## 2. Запуск store

На сервере:

```powershell
.\kilogram-ticket-store.exe `
  --listen 127.0.0.1:8787 `
  --data-dir C:\Kilogram\ticket-store-data `
  --retention-seconds 900 `
  --max-record-bytes 16777216 `
  --max-channels 100000 `
  --max-total-bytes 1073741824 `
  --per-ip-requests-per-minute 120 `
  --global-requests-per-minute 10000 `
  --max-concurrent-connections 128 `
  --trust-x-real-ip
```

На Linux синтаксис аргументов тот же. Каталог данных должен быть приватным и не
должен находиться внутри web root или синхронизируемой папки.

Ожидается:

```text
status=listening
listen_address=127.0.0.1:8787
transport_security=reverse-proxy-https-required
storage_format=opaque-redb-v1
```

## 3. Reverse proxy

Публичный URL должен передавать только точные API paths на
`http://127.0.0.1:8787`. Эквивалентная конфигурация обязана:

- принимать снаружи только HTTPS;
- ограничивать body 16 MiB или меньшим значением;
- разрешать только GET/PUT для `/v1/ticket-publications/`;
- полностью перезаписывать `X-Real-IP` фактическим адресом клиента;
- не писать полный request path в access log;
- буферизовать запрос до передачи backend;
- не публиковать никакие файлы из data directory.

Пример location-блока Nginx внутри уже настроенного HTTPS server:

```nginx
location = /healthz {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    access_log off;
}

location ^~ /v1/ticket-publications/ {
    client_max_body_size 16m;
    proxy_request_buffering on;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header Connection close;
    proxy_pass http://127.0.0.1:8787;
    access_log off;
}

location / {
    return 404;
}
```

Ограничение методов и внешние connection/rate limits желательно продублировать
на proxy/firewall. Не включайте `--trust-x-real-ip`, если proxy не перезаписывает
этот заголовок.

Проверка с Alice:

```powershell
Invoke-WebRequest https://store.example/healthz
```

Должны прийти HTTP 200 и `ok`.

## 4. Публикация Bob

Runtime Bob должен быть запущен и иметь актуальный public ticket. На Bob:

```powershell
.\kilogram-cli.exe runtime-ipc-publish-ticket `
  --ipc-file C:\Kilogram\private\bob-runtime.ipc.json `
  --conversation friends `
  --peer-account <ALICE_ACCOUNT_ID> `
  --service-base-url https://store.example `
  --ttl-seconds 900
```

Проверьте:

```text
ticket_publication_generation=...
ticket_publication_recipient_device_count=...
ticket_publication_upload=confirmed-http-success
status=runtime-own-ticket-published
```

Store и proxy не должны выводить ticket, Account ID, Device ID или conversation.

## 5. Получение Alice

На Alice:

```powershell
.\kilogram-cli.exe runtime-ipc-refresh-contact-ticket `
  --ipc-file C:\Kilogram\private\alice-runtime.ipc.json `
  --conversation friends `
  --peer-account <BOB_ACCOUNT_ID> `
  --service-base-url https://store.example
```

Первый успешный запуск должен показать `local_observation=Inserted` и
`descriptor_publish=atomic-replace`. Точный повтор должен показать
`local_observation=AlreadyPresent`. После этого обычная отправка или sync через
обновлённый contact descriptor должна достигнуть Bob.

## 6. Restart и retention

1. Остановите store через Ctrl+C, не удаляя data directory.
2. Запустите его снова с теми же параметрами.
3. Повторите refresh на Alice: та же публикация должна сохраниться.
4. Для отдельного короткого теста запустите чистый store с
   `--retention-seconds 30`, опубликуйте ticket и подождите более 30 секунд.
5. Refresh после cleanup должен получить HTTP 404, пока Bob не опубликует новый
   head.

Криптографический TTL Bob и service retention независимы. Ни один успешный GET
не продлевает срок хранения.

## 7. Что этот тест доказывает

Он доказывает реальный HTTPS publish/fetch между сетями, сохранение opaque bytes
после restart, ограниченное хранение и проверку ticket на конечном устройстве.

Он не доказывает сокрытие IP или social graph от глобального наблюдателя,
устойчивость к DDoS/Sybil, безопасность конкретной TLS-конфигурации, first-contact
freshness или невозможность denial-of-service со стороны знающего channel.
