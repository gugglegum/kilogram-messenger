# M0.3: проверка разных сетей в Windows

> Историческая процедура для M0.3/ticket v2. Текущий M0.7.4 CLI использует
> ticket v8, `--allow-account`, `--expect-account`, root-signed device list,
> prekey bundle каждого устройства и установленный conversation membership;
> актуальные контракты
> описаны в [`RFC-0002`](RFC-0002-account-device-authority.md) и
> [`RFC-0003`](RFC-0003-conversation-membership.md) и
> [`RFC-0004`](RFC-0004-pairwise-hpke-payload.md) и
> [`RFC-0005`](RFC-0005-local-encrypted-history-projection.md),
> [`RFC-0006`](RFC-0006-pairwise-double-ratchet.md) и
> [`RFC-0007`](RFC-0007-multi-device-ratchet-fanout.md).

Цель теста — отдельно доказать прямой NAT traversal и принудительный public
relay. Историческая M0.3 сборка не имела message-level E2EE; текущий HPKE spike
тоже ещё не production security. Не передавайте чувствительные данные.

## Схема

- Bob остаётся в домашней сети по Ethernet.
- Alice отключается от домашней LAN и подключается через мобильный hotspot или
  USB-модем. Проверить это можно по отсутствию доступа к локальному адресу Bob.
- Оба запускают `kilogram-cli.exe` из одной и той же распакованной тестовой
  сборки M0.3.
- Ticket передаётся Alice любым существующим каналом. Каждый перезапуск
  `listen` создаёт новый ticket; старый повторно не использовать.
- Все команды выполняются в PowerShell одной строкой. Обратные апострофы для
  переноса строк не нужны.

Ticket v2 этого build несовместим со старыми ticket v1. Старые каталоги state
совместимы, но для чистого теста ниже используются новые имена.

## 1. Подготовка Alice

Alice выполняет:

```powershell
$AliceState = '.\state-alice-m03'
.\kilogram-cli.exe identity --state-dir $AliceState
```

Alice отправляет Bob значение после `device_id=`. Bob сохраняет его:

```powershell
$AliceDeviceId = '<DEVICE_ID_ALICE>'
```

## 2. Принудительный direct через две сети

Bob запускает listener и не закрывает окно:

```powershell
.\kilogram-cli.exe listen --state-dir .\state-bob-m03 --allow-device $AliceDeviceId --ticket-file .\bob-direct.ticket --route-policy direct-only --relay-wait-seconds 30
```

После `status=listening` Bob передаёт Alice файл `bob-direct.ticket`. Alice
кладёт его рядом с EXE и выполняет:

```powershell
.\kilogram-cli.exe connect --state-dir $AliceState --ticket-file .\bob-direct.ticket --message 'hello from M0.3 cross-network direct test' --conversation 'm03-cross-network'
```

Успех direct-проверки на обеих сторонах:

```text
route_policy=direct-only
transport_ready_path=direct
status=acknowledged
transport_path=direct
```

Relay может участвовать в handshake и hole punching, но Kilogram не открывает
прикладной stream, пока Iroh не выберет direct IP path. Если NAT не допускает
прямое соединение, через 15 секунд команда должна завершиться явной ошибкой
`route policy direct-only was not satisfied ... selected path=relay`. Это
полезный отрицательный результат, а не повод повторять команду бесконечно.

## 3. Принудительный public relay

После завершения предыдущего listener Bob запускает новый:

```powershell
$RelayUrl = 'https://aps1-1.relay.n0.iroh.link./'
.\kilogram-cli.exe listen --state-dir .\state-bob-m03 --allow-device $AliceDeviceId --ticket-file .\bob-relay.ticket --route-policy relay-only --relay-url $RelayUrl --relay-wait-seconds 30
```

Bob передаёт Alice новый `bob-relay.ticket`. Alice выполняет:

```powershell
.\kilogram-cli.exe connect --state-dir $AliceState --ticket-file .\bob-relay.ticket --message 'hello from M0.3 cross-network relay test' --conversation 'm03-cross-network'
```

Ожидается на обеих сторонах:

```text
route_policy=relay-only
relay_status=online
relay_home_url=https://...
transport_ready_path=relay
status=acknowledged
transport_path=relay
transport_remote_address=relay:https://...
```

В этом режиме Iroh IP transports отключены у обоих endpoints, а signed ticket
содержит только Relay address. Dialing endpoint Alice использует relay из
подписанного ticket Bob как свой единственный home relay. Поэтому
`relay_home_url` Alice, `target_relay_url` Alice и `relay_home_url` Bob должны
совпадать. Если `relay_status` не становится `online` за 30 секунд, сохранить
ошибку и проверить обычный доступ в интернет.

Если Alice завершается с `connect to listening endpoint timed out`, сравнить:

- `target_endpoint_id` у Alice должен точно совпадать с
  `transport_endpoint_id` текущего процесса Bob;
- до попытки соединения обе стороны должны вывести `relay_status=online`;
- relay URL Alice и Bob должны совпадать;
- ticket надо копировать заново после каждого запуска `listen`.

Отсутствие `peer_id` означает, что QUIC-соединение с endpoint Bob ещё не
установлено: сообщение и проверка выбранного transport path на этом этапе не
начинались.

## 4. Reconnect после перезапуска Bob

Bob снова запускает listener с тем же state, но новым ticket:

```powershell
.\kilogram-cli.exe listen --state-dir .\state-bob-m03 --allow-device $AliceDeviceId --ticket-file .\bob-relay-sync.ticket --route-policy relay-only --relay-url $RelayUrl --relay-wait-seconds 30
```

После передачи нового ticket Alice выполняет:

```powershell
.\kilogram-cli.exe sync --state-dir $AliceState --ticket-file .\bob-relay-sync.ticket --conversation 'm03-cross-network'
```

Ожидаемый итог:

```text
route_policy=relay-only
transport_ready_path=relay
sync_rounds_completed=1
sync_more_available=false
status=synchronized
transport_path=relay
```

## 5. Что прислать разработчику

Нужны полные консольные логи Alice и Bob для direct-only, relay-only и sync.
Ticket можно не скрывать: это публичные адресные данные без секретных ключей.
Не присылайте файлы `device-secret.key` и целиком каталоги `state-*`.
