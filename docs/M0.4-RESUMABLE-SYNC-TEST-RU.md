# M0.4: pause/reconnect sync при смене сети

> Историческая процедура для зафиксированной M0.4/ticket v2 сборки test7.
> Текущий M0.7.1 CLI использует ticket v5, `--allow-account`,
> `--expect-account`, enrolled devices и установленный conversation
> membership; encrypted `seed-history` дополнительно требует
> `--peer-certificate-file`. См. [`RFC-0002`](RFC-0002-account-device-authority.md),
> [`RFC-0003`](RFC-0003-conversation-membership.md) и
> [`RFC-0004`](RFC-0004-pairwise-hpke-payload.md).

Цель — доказать, что полностью сохранённый sync round не повторяется после
остановки, смены transport Endpoint и перехода одного компьютера из домашней
LAN в мобильную сеть. Это development-прототип без message-level E2EE: не
используйте чувствительные сообщения.

Для теста нужны два Windows-компьютера с одной сборкой M0.4. Alice остаётся в
домашней LAN. Bob сначала находится в той же LAN, затем переключается на hotspot
телефона с отключённым Wi-Fi телефона, чтобы интернет действительно шёл через
cellular. Все команды ниже однострочные PowerShell-команды.

## 1. Новые состояния и общий базовый event

Alice:

```powershell
$AliceState = '.\state-alice-m04'; .\kilogram-cli.exe identity --state-dir $AliceState
```

Bob сохраняет выведенный Alice `device_id`:

```powershell
$AliceDeviceId = '<DEVICE_ID_ALICE>'; $BobState = '.\state-bob-m04'
```

Пока оба компьютера находятся в домашней LAN, Bob запускает:

```powershell
.\kilogram-cli.exe listen --state-dir $BobState --allow-device $AliceDeviceId --ticket-file .\bob-m04-base.ticket --route-policy direct-only --relay-wait-seconds 30
```

После `status=listening` Bob передаёт Alice свежий `bob-m04-base.ticket`.
Alice выполняет:

```powershell
.\kilogram-cli.exe connect --state-dir $AliceState --ticket-file .\bob-m04-base.ticket --message 'M0.4 shared base' --conversation 'm04-resume'
```

Обе стороны должны получить `status=acknowledged` и `transport_path=direct`.
Теперь у каждой стороны есть два общих events: сообщение Alice и
acknowledgement Bob. Это также даёт listener доказательство, что Alice уже
является author данной conversation.

## 2. Создание расхождения 70/70

Alice локально создаёт 70 своих fixture events:

```powershell
.\kilogram-cli.exe seed-history --state-dir $AliceState --conversation 'm04-resume' --count 70 --message-prefix 'alice'
```

Bob локально создаёт 70 других fixture events:

```powershell
.\kilogram-cli.exe seed-history --state-dir $BobState --conversation 'm04-resume' --count 70 --message-prefix 'bob'
```

На обеих сторонах ожидаются `seeded_event_count=70`, `event_count=72` и
`status=seeded`. `seed-history` существует только как development test helper.

## 3. Первый round и штатная пауза в LAN

Bob, всё ещё в домашней LAN, запускает новый listener:

```powershell
.\kilogram-cli.exe listen --state-dir $BobState --allow-device $AliceDeviceId --ticket-file .\bob-m04-pause.ticket --route-policy direct-only --relay-wait-seconds 30
```

После передачи Alice нового ticket Alice запускает только один round:

```powershell
.\kilogram-cli.exe sync --state-dir $AliceState --ticket-file .\bob-m04-pause.ticket --conversation 'm04-resume' --max-rounds 1
```

Ожидается на обеих сторонах:

```text
sync_round_1_sent_events=64
sync_round_1_received_events=64
sync_rounds_completed=1
sync_more_available=true
sync_resume_checkpoint=event-store
status=paused
transport_path=direct
```

После этого обе команды завершаются штатно. В каждом store теперь 136 events:
2 общих + 70 локальных + 64 полученных.

## 4. Смена сети и продолжение через relay

Bob отключается от домашней LAN и подключает ноутбук к hotspot телефона.
На телефоне нужно отключить Wi-Fi, оставив cellular data. Bob запускает новый
listener с тем же `$BobState`, но новым transport Endpoint и pinned relay:

```powershell
.\kilogram-cli.exe listen --state-dir $BobState --allow-device $AliceDeviceId --ticket-file .\bob-m04-resume.ticket --route-policy relay-only --relay-url 'https://aps1-1.relay.n0.iroh.link./' --relay-wait-seconds 30
```

Bob передаёт Alice новый `bob-m04-resume.ticket`. Старый ticket использовать
нельзя. Alice продолжает sync без ограничения в один round:

```powershell
.\kilogram-cli.exe sync --state-dir $AliceState --ticket-file .\bob-m04-resume.ticket --conversation 'm04-resume'
```

Критерий успеха на обеих сторонах:

```text
sync_round_1_sent_events=6
sync_round_1_received_events=6
sync_rounds_completed=1
sync_more_available=false
status=synchronized
transport_path=relay
```

Новый `transport_endpoint_id` Bob должен отличаться от ID в pause ticket.
Передача ровно 6/6, а не 70/70, доказывает продолжение от durable event stores
после смены transport session. Старые signed inventory/diff при этом не
переиспользуются: новый round подписывается с новым session binding.

## 5. Финальная проверка истории

Alice и Bob выполняют соответственно:

```powershell
.\kilogram-cli.exe history --state-dir $AliceState --conversation 'm04-resume'
```

```powershell
.\kilogram-cli.exe history --state-dir $BobState --conversation 'm04-resume'
```

У обеих сторон должно быть `event_count=142`. Значения `frontier` и весь набор
строк `event_id=` должны совпасть. Логи pause и resume обеих сторон нужно
сохранить целиком: они закроют внешний критерий M0.4.

## 6. Подтверждённый результат test7

Внешний прогон завершён 2026-08-31 с Run ID `20260831-055424` и conversation
`m04-test7-20260831-055424`:

- pause transfer: 64/64 по direct LAN;
- после переключения Bob на cellular resume transfer: 6/6 через relay;
- обе стороны завершили sync без повторной передачи первого batch;
- `event_count=142`, `frontier_count=2`;
- полные детерминированные outputs `history` Alice и Bob совпали.

Автоматическая финальная проверка сообщила
`TEST7 COMPLETED SUCCESSFULLY: histories are identical.` M0.4 считается
завершённым.
