# M0.9.60: набор приёмочного теста M1

Статус: инструменты готовы и проверены без сети. Сам тест Alice/Bob запускается
только вручную, когда оба компьютера доступны.

## Что такое HTTPS mailbox store

Это временный «почтовый ящик» для зашифрованных пакетов. Если Alice недоступна,
Bob кладёт туда ciphertext. Позже Alice забирает его, проверяет и расшифровывает
локально, сохраняет сообщение у себя и только после этого удаляет пакет из
ящика.

Сервис не получает текста сообщения или ключа расшифрования. Но он видит IP,
время, размеры запросов и обращения к одному непрозрачному mailbox. Он также
может отказать в обслуживании или потерять пакет, поэтому это помощник
доступности, а не доверенный участник переписки.

Операционная система не принципиальна: `kilogram-ticket-store` написан на Rust
и может работать на Windows или Linux. Для постоянной службы удобнее Linux/VPS.

## Самый простой вариант для нашего теста

Можно запустить `kilogram-ticket-store` отдельным процессом на Alice. Рядом
должен постоянно работать HTTPS reverse proxy (Caddy/Nginx), принимающий 443 и
пересылающий запросы на `127.0.0.1:8787`.

В phase 05 выключаем **только** runtime и GUI Alice. Компьютер Alice, store и
HTTPS proxy не выключаем. Если выключить весь компьютер, Bob некуда будет
положить пакет — такой эксперимент потребует VPS или третьего always-on peer.

Если Bob находится в той же LAN, HTTPS-имя должно разрешаться в LAN-адрес Alice,
а сертификат должен быть доверен обычным Windows trust store на обоих ПК. Если
Bob находится в 4G, нужны реально доступные извне имя и TCP 443; при CGNAT
обычный port forwarding не поможет. Не публикуйте наружу порт 8787: store
намеренно слушает только loopback HTTP.

Пример запуска store из рабочей копии на Alice:

```powershell
powershell -ExecutionPolicy Bypass `
  -File .\scripts\invoke-cargo-friendly.ps1 `
  build -CargoJobs 4 --locked --package kilogram-ticket-store

.\target\debug\kilogram-ticket-store.exe `
  --data-dir C:\Kilogram\private\mailbox-store-data 2>&1 |
  Tee-Object C:\Kilogram\private\mailbox-store-startup.log
```

Это foreground-процесс. Оставьте окно открытым. Строку
`blind_mailbox_store_key=...` перенесите в manifest. Настройка домена,
сертификата и reverse proxy зависит от выбранной сети и в набор автоматически
не входит.

## Создание переносимого набора

В чистой рабочей копии проекта на Alice:

```powershell
powershell -ExecutionPolicy Bypass `
  -File .\scripts\new-kilogram-m1-acceptance-kit.ps1 `
  -CargoJobs 4
```

Скрипт выдаст `acceptance_kit_directory=...`. Он создаёт обычную папку, не ZIP,
и собирает только debug EXE. Никакой сетевой процесс при создании не стартует.
Скопируйте папку на Bob или положите её в синхронизируемый каталог.

Внутри всегда два клиентских файла со стабильными именами:

- `bin\kilogram-cli.exe`;
- `bin\kilogram-windows.exe`.

`kilogram-ticket-store.exe` в переносимый клиентский набор не входит: это
отдельно разворачиваемая служба. При варианте store-on-Alice его достаточно
собрать/запустить из рабочей копии Alice.

## Локальные конфиги и evidence

На каждом ПК создайте приватную папку, например `C:\Kilogram\private`. Скопируйте
туда соответствующий `alice.local.example.psd1` или
`bob.local.example.psd1`, уберите `.example` из имени и исправьте пути.

Настоящий config, runtime profile, IPC descriptor и state нельзя класть в
Yandex Disk или внутрь набора/evidence. Они могут содержать локальные адреса и
bearer token. Startup stdout store — исключение: после проверки, что в нём нет
application IDs, Alice копирует его как
`C:\Kilogram\shared-staging\mailbox-store-startup.log`, а Bob указывает этот
путь в своём config. Это публичные параметры/лимиты и public store key, а не
read/write capability. Синхронизируется evidence и этот staging-файл, но не
private state.

В evidence скопируйте `manifest.example.json` как `manifest.json`, заполните все
поля согласно M0.9.58. `build_commit` уже взят из сборки и менять его нельзя.

Проверить список действий:

```powershell
powershell -ExecutionPolicy Bypass -File .\RUN.ps1 -ListSteps
```

Каждое действие запускается так:

```powershell
powershell -ExecutionPolicy Bypass -File .\RUN.ps1 `
  -Step store-preflight `
  -ConfigFile C:\Kilogram\private\bob.local.psd1 `
  -EvidenceDirectory C:\Kilogram\shared-evidence\RUN-ID
```

Driver перед каждым шагом сверяет SHA-256 обоих EXE с `BUILD-INFO.json`. Уже
существующие evidence-файлы не перезаписываются.

## Порядок шагов

Полный смысл пауз, действий GUI и ожидаемых состояний описан в
`M0.9.58-MAILBOX-LIFECYCLE-FIELD-TEST-RU.md` в репозитории. Краткий порядок
driver-команд:

1. На Alice уже работают store и HTTPS proxy; Bob: `store-preflight`. Именно
   запуск с Bob доказывает cross-machine reachability и обычное TLS trust.
2. Alice: `alice-01-start`; Bob: `bob-01-start-lost-ack`; в GUI Alice —
   Activate; Alice: `alice-01-capture-pending`.
3. Bob: `bob-02-start`; Alice: `alice-02-start`; затем соответствующие
   `capture-active` на обоих ПК.
4. В GUI Alice при остановленном Bob — Rotate и
   `alice-03-capture-rotation-pending`; затем `bob-04-start`,
   `alice-04-start` и оба `capture-rotated`.
5. Полностью остановить runtime/GUI Alice, но оставить её store/proxy/ПК.
   Bob: `bob-05-start-send`; после `mailbox-stored` остановить Bob. Alice:
   `alice-05-start-receive`, затем `alice-05-capture-mailbox`.
6. В GUI Alice при остановленном Bob — Revoke и
   `alice-06-capture-revocation-pending`; затем `bob-07-start`,
   `alice-07-start` и оба `capture-revoked`.
7. На одном ПК после синхронизации: `copy-boundaries`, затем `verify`.

Runtime-шаги работают foreground и должны пересекаться во времени там, где
Alice и Bob соединяются. Поэтому используйте отдельное PowerShell-окно для
status-команды и GUI. Не запускайте два runtime над одной state directory.

Успешный финал содержит `result : verified`. Это и будет машинная часть
приёмки; отображение состояний в GUI оператор подтверждает отдельно.
