# RFC-0137: Canonical prekey selection transcript (M1.1.11)

Status: candidate, not active.

## Outcome

M1.1.11 closes the last known gap in the public ratchet-artifact surface. A
portable participant can now derive the same one-time prekey from an exact
signed pool without inheriting Rust integer layout or Postcard serialization.
The active algorithm and active wire format do not change.

## Transcript

`CANONICAL-PREKEY-SELECTION.cddl` defines a six-item transcript containing the
initiator Device ID, exact canonical signed pool bytes, selection digest,
selected index and selected prekey sequence. The nested pool is signature-
verified and bounded to 512 KiB before selection.

The pool ID commits to the exact signed pool. The selection input is canonical
CBOR `[1, initiator-device-id, pool-id]`; BLAKE3 hashes its domain-prefixed exact
bytes. The first eight digest bytes are interpreted as an unsigned big-endian
integer and reduced modulo the verified pool size. The selected sequence must
equal the bundle at that index. Digest, index and sequence are deliberately
redundant so a stored transcript is self-describing, but every field is
recomputed and mismatch fails closed.

This differs intentionally from the active v1 selector, which hashes Device IDs
and a little-endian generation. Reusing its protocol identity would therefore
be a downgrade/interoperability bug. Activation requires the separate canonical
migration contract and a new explicit identifier.

## Security boundary

The transcript proves deterministic selection from an authentic pool; it is
not proof that the named initiator controls its Device key. Session
authentication supplies that fact. Decoder verification is also independent of
wall-clock time: the caller must enforce pool freshness against its signed
validity interval.

The exact vector is regenerated by an independent JavaScript encoder using the
independent BLAKE3 reference. It fixes pool ID, selection input, digest, explicit
big-endian prefix, index, sequence, selected bundle and full transcript bytes.
The strict decoder joins the bounded corpus, increasing it from 2,610 to 2,871
malformed cases without raising the 3,000-case ceiling.

## Activation boundary

This stage changes no active wire bytes and assigns no protocol identifier. It
only completes the audited `ratchet-public-artifacts` canonical surface.
