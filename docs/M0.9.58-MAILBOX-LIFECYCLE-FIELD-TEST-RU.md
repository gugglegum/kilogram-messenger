# M0.9.58: двухмашинный field test жизненного цикла mailbox

Статус: сценарий и проверяющие инструменты готовы. Сам сетевой тест ещё не
запускался. Его нужно проводить отдельно, когда доступны Alice, Bob и публичный
HTTPS mailbox store.

## 1. Что проверяем

Один прогон должен показать:

1. activation по прямому соединению;
2. принудительную потерю ACK уже **после** durable commit на Bob;
3. `activation-pending` на Alice, restart обоих процессов, exact retry и
   `AlreadyPresent` на Bob;
4. `rotation-pending`, затем convergence rotation через relay;
5. одно сообщение Bob → Alice через blind mailbox при выключенной Alice;
6. `revocation-pending`, затем convergence revocation;
7. одинаковые generation/update/binding в status Alice и Bob;
8. те же состояния в панели **Blind mailbox fallback** Windows-клиента.

Для direct-фазы удобнее оставить оба компьютера в одной LAN. Для relay-фазы
один компьютер можно перевести на мобильный интернет и использовать
`relay-only` runtime ticket. VPN на время измерения лучше отключить, иначе тест
будет характеризовать VPN-маршрут.

## 2. Что потребуется

- один и тот же debug commit на Alice и Bob;
- стабильные имена `kilogram-cli.exe` и `kilogram-windows.exe`;
- уже связанные аккаунты, current device rosters, контакт и общий private-chat
  conversation;
- отдельный локальный runtime profile и IPC descriptor на каждой машине;
- публичный HTTPS `kilogram-ticket-store` с mailbox API и сохранённым startup
  log;
- новая пустая общая папка `evidence` для **публичных логов**, но не для state,
  profile или IPC файлов.

Этот этап ничего не собирает и не архивирует. Debug EXE переносим только перед
реальным тестом. Не кладите в синхронизируемую папку seed, `device-secret.key`,
vault key, state directory, runtime profile или IPC descriptor с bearer token.

## 3. Manifest

В `evidence\manifest.json` создайте:

```json
{
  "schema": 1,
  "run_id": "20260906-120000",
  "build_commit": "abcdef1",
  "conversation_id": "64 lowercase hex chars",
  "alice_account_id": "64 lowercase hex chars",
  "alice_device_id": "64 lowercase hex chars",
  "bob_account_id": "64 lowercase hex chars",
  "bob_device_id": "64 lowercase hex chars",
  "mailbox_service_url": "https://store.example",
  "mailbox_store_key": "64 lowercase hex chars",
  "activation_route": "direct",
  "rotation_route": "relay",
  "revocation_route": "relay"
}
```

`conversation_id` берётся из строки mailbox status, а не является текстовым
conversation label. Store key должен совпасть со строкой
`blind_mailbox_store_key` сервиса.

Ни один phase-файл не перезаписывается: для повтора создавайте новую папку с
новым `run_id`.

## 4. Общие команды

В примерах `$Repo`, `$Evidence`, `$Profile`, `$Ipc` и `$Cli` — **локальные** пути
конкретного компьютера:

```powershell
$Repo = 'E:\AI-Projects\kilogram-p2p-messenger'
$Evidence = 'C:\Kilogram\field-test\evidence'
$Profile = 'C:\Kilogram\private\runtime-profile.json'
$Ipc = 'C:\Kilogram\private\runtime.ipc.json'
$Cli = "$Repo\target\debug\kilogram-cli.exe"
```

Запуск runtime с записью phase log:

```powershell
powershell -ExecutionPolicy Bypass -File "$Repo\scripts\invoke-kilogram-mailbox-field-runtime.ps1" `
  -Role alice -Phase 02-retry -ProfileFile $Profile `
  -EvidenceDirectory $Evidence -CliPath $Cli
```

Снятие status:

```powershell
powershell -ExecutionPolicy Bypass -File "$Repo\scripts\capture-kilogram-mailbox-field-status.ps1" `
  -EvidenceFileName 02-alice-active.status -IpcFile $Ipc `
  -EvidenceDirectory $Evidence -CliPath $Cli
```

Runtime остаётся foreground-процессом. Для одновременной работы GUI и status
откройте отдельные PowerShell окна. GUI подключайте к тому же локальному IPC;
не запускайте второй runtime на той же state directory.

## 5. Phase 01 — activation и потерянный ACK

1. Запустите Alice runtime с phase `01-lost-ack` без fault switch.
2. На Bob запустите получателя:

```powershell
powershell -ExecutionPolicy Bypass -File "$Repo\scripts\invoke-kilogram-mailbox-field-runtime.ps1" `
  -Role bob -Phase 01-lost-ack -ProfileFile $Profile `
  -EvidenceDirectory $Evidence -CliPath $Cli `
  -DropMailboxCapabilityAckAfterApplyOnce
```

3. В GUI Alice выберите exact Bob Device, HTTPS URL/store key и нажмите
   **Activate**.
4. Bob должен сам завершиться с
   `runtime_stop_reason=debug-mailbox-capability-ack-drop`.
5. Пока Alice runtime работает, сохраните
   `01-alice-pending.status`. GUI должен показать `activation-pending`.
6. Остановите Alice штатно. Не удаляйте state ни на одной стороне.

Fault нельзя использовать на пользовательских данных вне этого контролируемого
прогона. Он присутствует только в debug build и специально останавливает Bob.

## 6. Phase 02 — restart и exact retry

1. Перезапустите Bob **без** fault switch с phase `02-retry`.
2. Перезапустите Alice с phase `02-retry`.
3. Дождитесь ACK. В Alice log должны появиться generation 1,
   `runtime_mailbox_capability_update_status=acknowledged` и выбранный direct
   path; в Bob log — `mailbox_capability_update_store=AlreadyPresent`.
4. Сохраните `02-alice-active.status` и `02-bob-active.status`.
5. В обоих GUI обновите mailbox status: generation 1 должна быть `active`.

## 7. Phases 03–04 — rotation overlap и relay convergence

1. Остановите Bob.
2. На работающей Alice нажмите **Rotate** с тем же HTTPS URL/key.
3. Сохраните `03-alice-rotation-pending.status`; GUI должен показать
   `rotation-pending`. Это наблюдаемое окно, в котором previous acknowledged
   receive binding остаётся overlap-кандидатом.
4. Остановите Alice.
5. Переведите один хост в другую сеть, запустите Bob с relay-only profile и
   phase `04-rotation`. Дождитесь публикации/refresh нового current Bob ticket.
6. Запустите Alice с phase `04-rotation` и дождитесь generation 2 ACK через
   relay.
7. Сохраните `04-alice-rotated.status` и `04-bob-rotated.status`; оба GUI должны
   показывать generation 2 `active`.

## 8. Phase 05 — opaque mailbox round trip

1. Скопируйте только startup stdout mailbox service в `05-store.log`. В нём
   обязательны `storage_format=opaque-redb-v1`, public store key и требование
   reverse-proxy HTTPS. Полные HTTP paths в proxy access log должны быть
   отключены.
2. Остановите Alice полностью.
3. Запустите Bob с phase `05-mailbox-send`, отправьте Alice одно уникальное
   тестовое сообщение и дождитесь `runtime_outbound_status=mailbox-stored`.
4. Остановите Bob, запустите Alice с phase `05-mailbox-receive` и дождитесь
   `runtime_mailbox_inbound_status=deleted-after-commit`.
5. Сохраните `05-alice-mailbox.status`; receive и deleted counters должны быть
   не меньше одного.

Store-signed receipt и клиентский E2EE round trip доказывают принятие opaque
envelope данным store. Они не доказывают отсутствие скрытого логирования на
чужом сервере и не скрывают timing/volume.

## 9. Phases 06–07 — revocation

1. Остановите Bob.
2. На Alice нажмите **Revoke**, сохраните
   `06-alice-revocation-pending.status`; GUI должен показать
   `revocation-pending` generation 3.
3. Остановите Alice.
4. Запустите Bob и Alice с phase `07-revocation`, дождитесь ACK по маршруту из
   manifest.
5. Сохраните `07-alice-revoked.status` и `07-bob-revoked.status`; оба GUI должны
   показывать generation 3 `revoked`.

## 10. Boundary evidence и финальная проверка

На commit, из которого собраны debug EXE, объедините вывод следующих scripts в
`08-boundaries.log`:

```powershell
$checks = @(
  'verify-kilogram-mailbox-boundary.ps1',
  'verify-kilogram-runtime-mailbox-flow.ps1',
  'verify-kilogram-mailbox-capability-lifecycle.ps1',
  'verify-kilogram-mailbox-capability-convergence.ps1',
  'verify-kilogram-mailbox-desktop-control.ps1',
  'verify-kilogram-mailbox-field-test-boundary.ps1'
)
foreach ($check in $checks) {
  & powershell -ExecutionPolicy Bypass -File "$Repo\scripts\$check" 2>&1 |
    Tee-Object -FilePath "$Evidence\08-boundaries.log" -Append
  if ($LASTEXITCODE -ne 0) { throw "$check failed" }
}
```

После синхронизации всех файлов:

```powershell
powershell -ExecutionPolicy Bypass `
  -File "$Repo\scripts\verify-kilogram-mailbox-field-evidence.ps1" `
  -EvidenceDirectory $Evidence
```

Успех заканчивается `result : verified`. Отдельно Alice и Bob устно
подтверждают, что GUI показал `activation-pending → active`,
`rotation-pending → active` и `revocation-pending → revoked`. Скрипт намеренно
не выдаёт человеческое наблюдение за машинно проверенный факт.
