# Kilogram: простая терминальная переписка

Это кандидат для проверки. Связь через разные физические сети должна быть
проверена отдельно; наличие комплекта само по себе такого результата не доказывает.

Распакуйте **весь** комплект в постоянную папку и откройте `Start-Kilogram.cmd`
обычным пользователем Windows. Внутренние файлы находятся в `app`; переносить один
EXE отдельно не нужно. Администратор,
SSH и старый лабораторный controller для обычной переписки не нужны. Если Windows
спросит разрешение на сеть, это однократный выбор для постоянного пути приложения.

Первый участник нажимает Enter и сохраняет показанные recovery words вне чата.
Подтвердите `/saved`, затем отправьте собеседнику **одну** строку
`kilogram://peer/...` по доверенному каналу. Второй участник вставляет эту строку
на стартовом экране своего комплекта, принимает приглашение и сохраняет собственные
recovery words. Первый участник подтверждает выбранного собеседника. Технические
подписи, consent и адреса обмениваются автоматически; файлы и IP вводить не нужно.
На сохранение recovery words и подтверждение собеседника нет короткого сетевого
таймера. `/quit`, закрытие ввода и Ctrl-C отменяют ожидание; signed consent всё
равно проверяется на срок действия при исполнении протокола.

Когда переписка открыта, пишите обычный текст и нажимайте Enter. `/status`
показывает состояние, `/history` — сохранённую историю, `/history more` — её
продолжение, `/quit` — штатный выход. Повторный запуск той же папки открывает тот же
аккаунт. При недоступном собеседнике подтверждённые сохранённые сообщения остаются
локально и должны доставляться после его возвращения. Не повторяйте сообщение при
неясном подтверждении: проверьте историю. `/resync` повторно показывает сохранённое,
если позиция автоматического отображения повреждена; сообщения не переотправляются.

Не удаляйте и не переносите папку `profile` между пользователями или машинами:
Windows защищает ключи привязкой к текущему пользователю. Существующие аккаунты
ручного pilot не удаляйте и не заменяйте новым профилем. В комплекте для каждого
ПК есть `Open-existing-pilot.cmd` с его прежним путём: перед переходом закройте
старое окно аккаунта самостоятельно. Если оно ещё работает, новый запуск должен
отказать, сохранив профиль. Первый технический переход требует одной новой ссылки
между **прежними** собеседниками; чужое приглашение к уже выбранной паре отклоняется.
Пересоздавать identity и переносить файлы аккаунта для этого не требуется.

Приглашение содержит возможность подключения, endpoint и отпечаток публичного
аккаунта. Оно связывает обмен с полученной ссылкой, но не удостоверяет реальное имя
человека. Не публикуйте ссылку: передавайте её тому человеку, с которым собираетесь
переписываться. Recovery words и приватные ключи собеседнику не передаются.

Сообщения и история остаются на устройствах; транспорт сохраняет E2EE. Для поиска
адреса и прохождения NAT используется Iroh; по умолчанию выбран публичный HTTPS
relay Iroh EU. Это внешняя инфраструктура rendezvous/передачи зашифрованных пакетов,
не сервер аккаунтов или истории. Она видит сетевые metadata, включая endpoint и
адрес подключения; её доступность не гарантируется. Приложение показывает
подтверждённый прямой либо relay-путь, когда runtime может его установить. Один
успешный тест не доказывает доступность через любой NAT или фильтр.

Текущая граница: Windows, один выбранный собеседник на профиль, терминальный
интерфейс. Группы, каналы, GUI, общий каталог контактов, перенос аккаунта на другое
устройство и удобное продление consent ещё не являются завершённым продуктом.

`Network-test.cmd` — отдельный ограниченный тест на одноразовом аккаунте, не
обычная переписка. Его запускают только при согласованной проверке: вставляют одну
ссылку из PC probe, далее ответы и завершение автоматические. Он не открывает
личный `profile` и сохраняет результат в `app/test-data`. Локальная проверка этого
receiver не доказывает связь через разные сети; такой результат отмечается отдельно.
