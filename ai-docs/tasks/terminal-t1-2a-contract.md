# T1.2a. Создание локального Setup из терминала

База `81c493b61c54aebbeef9970f01fa048621817133`. Цель T1.2 — два пользователя начинают с пустых каталогов, создают свои профили, сохраняют слова восстановления, обмениваются публичными файлами, задают LAN и переходят к `chat`. Существующий Setup содержит два контекста одного peer. [Контракт T1](terminal-t1-contract.md) · [Полевой пилот готовых Setup](terminal-t1-1f-result.md)

## Первый срез

Добавить `kilogram-cli setup --dir <каталог> [--jsonl] [--allow-recovery-output]` для Windows. Открытие программы запускает только обработчик stdin/stdout. Команды позволяют начать Setup приглашающей стороны, создать аккаунт и устройство, открыть сохранённое состояние и явно подтвердить сохранение слов. Пользователь завершает `setup` для освобождения блокировки каталога. В T1.2a обмен с peer и запуск runtime находятся за границей среза.

`Setup::begin(.., None)` сохраняет `setup.json` с новым invitation ID и двумя различными ID контекстов. `helper::run` передаёт эти контексты в `create-ordered2`, а bootstrap закрепляет их в репозитории до публикации `bootstrap-ready.json`. Для join нужны контексты и проверенный отправитель из приглашения до создания аккаунта. Завершённый inviting Setup поэтому предназначен для последующего экспорта своего приглашения. Для join в следующем срезе используется `Setup::begin(.., Some(invite))` на пустом каталоге, затем те же команды создания и сохранения слов. [Begin и join](../../crates/kilogram-first-dialog/src/model.rs#L127) · [Привязки helper](../../crates/kilogram-first-dialog/src/helper.rs#L110) · [Durable commit bootstrap](../../apps/kilogram-bootstrap/src/ordered2.rs#L195)

Использовать `model::Setup` и `helper::run` из `kilogram-first-dialog`, действующие форматы record/receipts и штатный DPAPI CurrentUser. Helper берётся по абсолютному пути рядом с запущенным `kilogram-cli.exe`, как в GUI. При отсутствии helper вернуть код ошибки. Аргументы child содержат только workspace и контексты. Секретный результат helper принимается по его приватному pipe с существующими лимитом 64 КиБ, таймером 60 с и проверкой завершения. При создании и повторном открытии проверять `windows-dpapi-current-user`. Для принятия результата использовать `Setup::accept`, который сверяет generation, workspace, контексты и пару public receipts. [Выбор helper в GUI](../../apps/kilogram-windows/src/lib.rs#L220) · [Сбор результата](../../crates/kilogram-first-dialog/src/helper.rs#L42) · [Accept и acknowledge](../../crates/kilogram-first-dialog/src/model.rs#L313)

## Команды

TTY получает одну команду на строку. JSONL использует существующее framing T1 v1, UTF-8 без BOM, одну строку до 32 КиБ и запрос `{"v":1,"id":"1","op":"status","args":{}}`. Имена и поля проверяются строго. При открытом stdout команды возвращают один `{"v":1,"type":"result","id":"1","ok":true,"value":…}` или `{"v":1,"type":"result","id":"1","ok":false,"code":"…"}`. Ошибка framing и повтор активного `id` дают `{"v":1,"type":"frame_error","code":"…"}`. Writer освобождает внешнее резервирование `id` перед первым байтом ответа. Допуск мутаций по-прежнему ждёт завершения worker и подтверждения записи. Cancel связывается с внутренним поколением при приёме. Поздний ACK не снимает резерв повторно использованного `id`. При запуске JSONL печатает `{"v":1,"type":"ready"}`. [Framing и correlation T1](../../apps/kilogram-cli/src/terminal_chat.rs#L799) · [Публикация T1.1c](../../apps/kilogram-cli/src/terminal_chat/coordinator.rs#L270)

| TTY | JSONL op и args | Успех |
| --- | --- | --- |
| `/status` | `status {}` | Снимок `S`. |
| `/begin` | `begin {}` | Создать запись приглашающей стороны под lock и вернуть `S`. |
| `/open` | `open {}` | Открыть существующую запись под lock, сверить привязки и вернуть `S`. Повтор на уже открытом Setup показывает текущее состояние, сохраняя доступные слова. |
| `/create` | `create {}` | Создать аккаунт для подготовленной записи, вернуть `S` после принятия результата helper. |
| `/recovery show` | `recovery_show {}` | Показать слова по правилам ниже. JSONL `value={"recovery_words":"…","recovery_scope":"root-key-only-authority-history-required"}`. |
| `/recovery saved` | `recovery_ack {"saved":true}` | Я подтверждаю, что сохранил слова офлайн. После durable записи вернуть `S`. |
| `/cancel` | `cancel {"target_id":"<id команды create>"}` | Запросить отмену текущего создания, `value={"requested":true}`. Сам `create` получает собственный результат после завершения операции. |
| `/quit` | `quit {}` | Завершить работу, `value={"closed":true}` после подтверждённой уборки. |
| `/help` | — | Список TTY-команд и назначение сохранения слов. |

`S = {"state":"unopened","account_id":null,"device_id":null,"contexts":null}`. `state` принимает значения из таблицы ниже. `account_id` и `device_id` становятся строковыми ID после проверки ready. `contexts` становится упорядоченной парой строковых ID после begin/open. TTY показывает `Setup <state>` и, когда известны, строки `Account <id>` и `Device <id>`. Сообщения для `recovery_unavailable` и `incomplete` объясняют дальнейшее действие. Ошибки TTY содержат стабильный код и безопасную подсказку. Пути и аргументы трактуются как данные.

Основные отказы `setup_exists` (открыть известный Setup), `setup_missing`, `directory_not_empty`, `setup_locked`, `setup_invalid`, `not_open`, `busy`, `invalid_state`, `invalid_args`, `helper_unavailable`, `helper_failed`, `helper_timeout`, `cancelled`, `cleanup_unconfirmed`, `recovery_output_disabled`, `recovery_unavailable`, `recovery_show_required`, `not_active`, `too_late`. Отказ `create` после запуска сообщает код, а `status` показывает последнюю проверенную фазу. Преобразование ошибок helper/cleanup использует внутренние типизированные исходы. Сырые ошибки, stdout и stderr helper в ответ не попадают.

## Состояния и владение

| Состояние | Переход |
| --- | --- |
| `unopened` | `begin` резервирует отсутствующий или пустой каталог и сохраняет запись до запуска helper. `open` читает существующую валидную запись. `status` сам не создаёт каталог, lock или файлы. |
| `prepared` | Запись валидна, зарезервированный `account-<local_id>` отсутствует. Явный `create` допускается под тем же lock. Повтор `begin` возвращает `setup_exists`. |
| `creating` | В работе один принадлежащий сессии helper. Допускаются `status`, `cancel` и `quit`. Другие команды изменения получают `busy`. Успешное принятие текущего результата переводит в `recovery_available`. |
| `incomplete` | Workspace существует, готовый receipt отсутствует, durable ready ранее не подтверждался. Сохранить файлы. Если создание нужно начать заново, пользователь выбирает другой пустой каталог. |
| `recovery_available` | Ready и его привязки проверены, слова есть в памяти текущей сессии. Доступен явный показ. Подтверждение допускается после успешной записи и flush результата показа в этом сеансе. Повтор `create` не запускает helper. |
| `recovery_unavailable` | Ready найден и проверен, durable подтверждения нет, слов в памяти уже нет. Продолжить можно через `recovery_ack`, только если пользователь действительно сохранил слова раньше. Если копии нет, сохранить этот каталог и выбрать отдельный пустой Setup для нового аккаунта. Этот вход не восстанавливает слова. |
| `recovery_saved` | Durable подтверждение уже есть. Повтор `recovery_ack` с `saved:true` возвращает тот же снимок после проверки ready. Показ слов недоступен. |

`Setup::lock` уже берёт эксклюзивный `.onboarding.lock`, но текущий `open` создаёт родительский каталог, а текущий `begin` не проверяет пустоту целиком. Для терминала нужен guard в общей модели. До создания lock проверить ожидаемый обычный каталог и запись при open, либо отсутствие посторонних записей при begin, затем повторить проверку под тем же lock. Допускается штатный обычный lock-файл, оставшийся после завершённого процесса. Отвергать подмену каталога или рабочих файлов через symlink/reparse, повреждённую запись и чужие привязки. В GUI сохраняется существующий сценарий. Конкурирующий процесс не начинает второй helper и не правит чужие данные. [Lock, begin и open](../../crates/kilogram-first-dialog/src/model.rs#L75)

После cancel, таймаута, потери результата или сбоя helper дождаться завершения child и перечитать состояние средствами общей модели под lock. Если workspace ещё отсутствует, снова возможен явный `create`. Workspace без ready остаётся `incomplete` и повторный `create` отклоняется. Валидный ready при потерянном результате даёт `recovery_unavailable`. Повреждённый либо исчезнувший ранее подтверждённый ready даёт `setup_invalid` при повторной проверке. До подтверждённой уборки новые мутации получают `cleanup_unconfirmed`. Отмена и принятие результата сериализуются. Поздний результат отменённой операции уничтожается, а уже записанные файлы bootstrap остаются для проверки. Для нового открытия взять lock и заново проверить public receipts. Факт показа слов учитывается только в памяти этого сеанса. [Проверка ready при open](../../crates/kilogram-first-dialog/src/model.rs#L190) · [No-clobber bootstrap](../../apps/kilogram-bootstrap/src/ordered2.rs#L94)

## Показ и выход

В интерактивном TTY `/recovery show` явно выводит одну строку со словами. При перенаправленном stdout и в JSONL для этой команды требуется `--allow-recovery-output`. Флаг разрешает канал, а отдельная команда запрашивает показ. Для SSH без PTY пользовательский клиент посылает запрос на том же stdin и читает один помеченный ответ по его `id`, отключив запись этого ответа в transcript. Держать stdin открытым до ответа и явного `quit`. Использовать этот канал в приватном окне. После передачи байты могут остаться в клиенте или scrollback.

Показ использует отдельное представление секретного результата с зануляемым буфером и передачей владельца единственному writer. Обычный `S`, ошибки, диагностический stderr, логи, события и отчёты не содержат слов. Слова не принимаются во входе и не передаются через argv, env, clipboard или файлы приложения. В памяти можно повторить явно запрошенный показ до подтверждения. `recovery_ack`, пришедший сразу после чтения полного `recovery_show`, ждёт writer ACK конкретной записи до оценки команды. Только своевременный write+flush этого поколения и сеанса допускает подтверждение. При частичном выводе, ошибке или просроченном ACK подтверждение не допускается. Решение, что офлайн-копия действительно сохранена, принимает пользователь. После durable `Setup::acknowledge(true)` слова очищаются. Если ответ на подтверждение потерян, reopen показывает `recovery_saved`. Слова восстанавливают ключ и идентичность аккаунта. Для актуальной authority требуется отдельный пакет, для переписки — отдельный источник. [Область восстановления](../../crates/kilogram-bootstrap-contract/src/ordered2.rs#L7)

Один координатор управляет lock, одним worker и writer. Допускается одна выполняемая операция, одна ожидающая команда, до четырёх ожидающих кадров и один кадр у writer. Во время создания `status` выдаёт последний проверенный снимок с фазой `creating`. Он не читает Setup параллельно. Чтение stdin независимо от worker и writer, поэтому `cancel`, `quit` и EOF принимаются и при занятой записи. Переполнение выходной очереди завершает процесс с ошибкой. `quit` и EOF отменяют создание и ждут освобождения Setup. В консольном TTY Ctrl+C отменяет ожидающую команду или активное создание до принятия результата и сохраняет сеанс. В idle Ctrl+C закрывает сеанс. Короткая локальная операция, уже переданная worker, может закончиться. Pipe ETX остаётся входными данными.

Границы T1 составляют 256 КиБ на ответ, 3 с до подтверждения write+flush и 30 с на закрытие. Helper ограничен 60 с работы и 5 с подтверждения cleanup после отмены. Код процесса 0 означает штатный quit, EOF или idle Ctrl+C с освобождённым Setup. При сбое stdin/stdout, запуске на неподдерживаемой платформе или неподтверждённой уборке вернуть 2. Ошибка отдельной команды доступна в её результате и сама по себе не меняет код штатного завершения. При отказе записи подтверждение может быть потеряно. Stdio обслуживает один локальный запуск под текущим владельцем ОС, в том числе через SSH без отдельного listener.

## Сеанс

```text
PS> kilogram-cli setup --dir 'C:\Kilogram\Alice'
> /begin
Setup prepared
> /create
Setup recovery_available
> /recovery show
[24 слова в приватном терминале]
> /recovery saved
Setup recovery_saved
> /quit
PS> kilogram-cli setup --dir 'C:\Kilogram\Alice'
> /open
Setup recovery_saved
> /quit
```

## Приёмка

| Проверка | Критерий |
| --- | --- |
| Штатный путь на Windows | Два одноразовых локальных прогона через TTY и JSONL. Реальный sibling helper, DPAPI CurrentUser, неизменные локальные ID после reopen, два различных закреплённых контекста. Recovery подтверждается явно. Проверить совместимость открытия полученного Setup общей моделью. |
| Секретный вывод | Запуск JSONL без флага отклоняет show. С флагом слова появляются только в результате show, до `recovery_ack` доступны для явного повторного показа в своей сессии, после подтверждения или reopen недоступны. Проверить, что разобранная фраза соответствует account ID, затем очистить захваченный буфер. В квитанциях оставить коды, факт проверки и количество слов. Проверить обычные результаты, stderr, рабочие файлы и ошибки на отсутствие слов. |
| Конфликты и корреляция | Пустой, чужой непустой, повреждённый и подменённый каталог. Второй процесс, повтор begin/create, активный дубль `id`, немедленное повторное использование `id` и show → ack перед обработкой writer ACK. Позднее или старое подтверждение записи не разрешает новую мутацию. Проверить сохранность исходных файлов и единственный фактический helper. |
| Границы сбоя | Управляемые барьеры до резерва, после резерва и после ready до принятия приватного результата. Проверить cancel, EOF и отказ helper/вывода, фактический exit/reap, reopen в нужном состоянии, запрет переиспользования workspace и отсутствие авто-ACK. Отдельно потерять ответ успешного ACK и сверить durable `recovery_saved`. |

Тесты запускаются на свежих одноразовых каталогах. Для Windows harness соблюдать стабильные имена. Достаточны локальные тесты framing и состояний, сценарии контролируемых сбоев и два штатных прогона из таблицы.
