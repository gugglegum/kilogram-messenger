## 1. Adopt existing outer containment; do not create a second job subsystem

The original requirement must distinguish bounded local return from confirmed whole-attempt cleanup. No code can promise that every OS termination request succeeds. A local failure may return an explicitly unresolved cleanup outcome; it must never become success merely because a deadline elapsed, a handle dropped, or a kill was requested.

Root inspected scripts/migration-s5-l1-deadline.ps1. Its dedicated owner process enters a KILL_ON_JOB_CLOSE job with no breakaway, verifies its launched child handle's membership, retains the independent work/whole watchdog, enumerates actual job members and verifies membership again before termination. CleanupChildren has a finite bound; Finish refuses live children. Capture children launched without a breakaway flag are already contained by inheritance. They do not need a second Rust job assignment or process-name kill path.

Explicit amended ownership model:

- The outer dedicated job owner owns process-tree containment from before the stable harness launches until after the actual harness return and independent cleanup receipt. This is existing ownership, not a transfer inferred after losing a child. A Rust capture owner owns the concrete child handle and pipe handles only within that containment.
- Opt-in capture requires an explicit managed-launch/containment contract in addition to the existing deadline scope. For this slice's synthetic executions, the actual isolated wrapper must establish/verify the dedicated non-breakaway job before launching the stable runner, preserve the ancestor membership verification and collect cleanup result after actual test return. Use the existing wrapper/PS helper, not a new dependency, unsafe Rust, job implementation or Cargo target. An environment marker or JSON assertion alone is not runtime proof: bind the wrapper's actual launch, case/attempt, original owner identity and evidence; source-review inheritance and prohibit CREATE_BREAKAWAY_FROM_JOB/new process-launch escape flags. A small typed capture admission/context carrier and wrapper evidence seam are in scope. The future whole runner must supply equivalent independently verified facts before activation; unadmitted standalone opt-in must refuse before spawn.
- Use a capture-specific safe owner containing std::process::Child, with finite kill/try_wait handling and nonblocking handle close. Do not wrap it in the existing OwnedChild whose Drop calls unbounded wait; do not change that legacy type globally. Actual try_wait(Some(status)) is a confirmed observed exit, not an inferred success. Confirm both pipe EOFs and exit before ordinary successful return.
- On ordinary timeout/overflow/read/sanitizer error, terminate the known child, poll only within the explicit cleanup reserve and close owned pipe handles/readiness resources. No blocking wait or detached reader. Report whether exit/EOF/termination was actually confirmed. Preserve original absolute whole deadline; cleanup may use only its existing reserve, never restart it.
- If local exit remains unconfirmed, preserve safe child identity/command sequence/attempt/observed-error facts, mark the capture scope permanently failed, reject further successful work in that scope and return a bounded error with cleanup_pending=true. No raw bytes in this record. Dropping the local process HANDLE is not terminating the process and is not recorded as cleanup success; outer job containment remains armed. Constructor failures after spawn and unwinding follow the same ownership rule; arrange fallible allocations/registration before spawn where practical and keep the guard alive through cleanup. If writing the local record fails, the test still fails and the outer wrapper must still independently inventory and clean its job; do not convert absence of a record into proof of cleanup.
- The outer wrapper must independently record actual return and confirmed empty job, or classify the attempt cleanup-failed/aborted. An outer watchdog termination or missing final receipt cannot count as PASS. A locally unresolved real capture stays a failed functional capture even if later outer cleanup succeeds. Whole S54 cannot start until its final runner fulfills this contract. No full finalizer implementation is requested now; the actual synthetic wrapper evidence is required now.

This preserves the requirement that every successful accepted run has confirmed cleanup. It removes the impossible demand that the local helper prove OS termination even when it reports failure. It does not permit an uncontained child or a successful result with unresolved cleanup.
