# T1.2d.2. Выбор маршрута и переход к общению из терминала

База `2b2ad0b48d96a32016519314e73e333be5ad6823`. Команды `/route lan <local_ipv4> <peer_ipv4>` и `/route loopback` доступны в TTY и JSONL. Сохранение работает под существующим Setup lock. WinRT проверяет назначенный локальный IPv4 и фактический префикс общим валидатором runtime. Повтор маршрута сохраняет байты и mtime Setup. Смена маршрута сбрасывает текущий профиль и результаты импорта локаторов, сохраняя прежние файлы и ссылки на удержанный вход. [Контракт](terminal-t1-2d-contract.md) · [Команда](../../apps/kilogram-cli/src/terminal_setup/service.rs#L168) · [Проверка интерфейса](../../apps/kilogram-cli/src/ordered_dialog/runtime2/mod.rs#L28)

`connection.profile_state` различает точный профиль с подтверждённым digest, ожидание подготовки и конфликт. Известный существующий файл сравнивается с ожидаемым Profile2 даже до сохранения digest. Setup и Observer используют общую read-only проверку. Типы целей, reparse и границы локального каталога проверяются до mkdir и перед чтением профиля. Runtime по-прежнему запускается через отдельный `chat --setup` после `quit` и заново проверяет оба локальных согласия. [Пути и профиль](../../crates/kilogram-first-dialog/src/connection.rs#L208) · [Запуск owner](../../crates/kilogram-first-dialog/src/chat.rs#L110)

## Результаты Windows

- `build02` подтвердил offline locked сборку CLI, bootstrap и Windows GUI с Cargo Idle и одним заданием. Образы D.1 сверены по предыдущему манифесту, файлы D.2 заархивированы отдельно. [Образы и SHA-256](../../.tmp/terminal-t1-2d-2/build-images.json)
- `cli02` дал 12 успешных записей целевого фильтра Setup, включая разбор IPv4 и проверку, что подготовленный профиль не превращает устаревший consent в текущий. Последняя проверка использовала детерминированную границу времени. Сборка Windows GUI проверена без ручного прогона. `prefix02` подтвердил реальные правила для `/23` и `/25`. `shared02` подтвердил регрессию D.1 после изменения общего пути. [CLI](../../.tmp/terminal-t1-2d-2/cli02.stdout.log) · [Префикс](../../.tmp/terminal-t1-2d-2/prefix02.stdout.log) · [D.1](../../.tmp/terminal-t1-2d-2/shared02.stdout.log)
- `smoke01` прошёл на двух пустых каталогах без учётной фикстуры. Setup создал обе учётные записи, обменял приглашение, ответ и документы согласия и выполнил локальные импорты. На назначенном Windows IPv4 `172.18.0.1/30` проверены сохранение LAN-настроек, повтор без записи, reopen и отказ для непригодных адресов. Негативные сценарии отдельно проверили junction, подмену digest, несовместимый файл без digest и конфликт типа цели. После изменения маршрута все прежние файлы connection сохранили хеши.
- В том же прогоне оба Setup дошли через явный loopback и `quit` до chat owner. Старт с занятым Setup lock и второй owner получили отказ. До обмена локаторами локальный IPC работал без `live_admitted`. Затем оба owner подтвердили оба слота, доставили по сообщению в каждом контексте в разных направлениях и получили совпадающие строки истории. Observer проверил сохранённый профиль и покинул собственный сеанс. Оба owner завершились с кодом 0, их IPC-дескрипторы исчезли. [Сквозная квитанция](../../.tmp/terminal-t1-2d-2/native01/evidence.json)

Все зачётные квитанции подтверждают exit 0, EOF и пустой Windows Job без принудительной уборки. Первые компиляционные попытки `build01`, `cli01`, `prefix01` и `shared01` получили exit 0 дочернего процесса и после него завершили остаточный `vctip` в собственном Job. Эти квитанции сохранены. Передача сообщений по физической LAN и ноутбук в этот прогон не входили. Системные настройки не менялись.
