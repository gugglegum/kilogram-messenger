## Поведение и границы

- Start каждый раз проверяет оба exact retained CS1 finals, подтверждает либо восстанавливает реальные установки через прежние offline imports. Сохранённые acknowledgements сами ничего не разрешают. Конфликт, чужой lock и невалидные/отсутствующие finals блокируют Start, сохраняя данные. Profile2 создаётся без перезаписи или повторно используется после строгой проверки всех полей и digest. Local artifact ancestors проверяются на уход в device/Root и reparse points. Штатный restart сохраняет account/claim/device/contexts/consents/profile.
- `kilogram-runtime-ipc::ordered2` содержит общий serde Profile2 DTO и typed status/locator import/export/Shutdown. Missing quotas по-прежнему получают defaults в CLI; explicit null не допускается. Существующие authoritative route/quota/path/store checks сохранены. Старые CLI nested calls проверяют версию и совпадающий opcode. Descriptor identity проверяется на том же объекте, из которого берутся address/token; read ограничен16KiB, typed outer64KiB, nested reply48KiB. Поздняя замена файла не меняет client/адрес Shutdown.
- Runtime2 добавляет PID/instance и текущие `live_admitted`/`lease_expires` из прежних current-policy/Lease2 checks. Persisted `active` остаётся Ready state. UI требует живой owned Child, оба expected contexts/roles/consent refs, phase3/active, действующие leases и status моложе2s **от начала запроса**. Один in-flight, poll около1Hz, просроченные/отменённые generation ответы не оживляют badge. Immutable bindings проверяются при подготовке запуска; hot poll не повторяет offline ceremony validation. Текущая authority и lease проверяются runtime, а не кэшем UI.
- Новый strict `locators` envelope48KiB: frozen invitation, ordered contexts, 64-hex sender/recipient IDs и два signed Locator2 blobs до8192 bytes. Обе подписи, scope, интервалы и loopback route проверяются до первого import. Два локальных IPC commits не атомарны; per-slot outcome и exact retained bytes позволяют честно повторить частичный результат. Descriptor, token, claim, пути и ключи не экспортируются. Invite/reply/proposal/final wire untouched.
- Один worker владеет Setup и Child; IPC/start/exit/cleanup bounded5/30/10/5s, stdout/stderr rolling64KiB каждый, без показа raw output. Graceful stop требует ShutdownAccepted, owned exit0 и EOF. Forced/неподтверждённый stop не считается graceful. Close/leave отменяют работу и останавливают собственный runtime; foreign PID не усыновляется и не завершается. Reopen начинает с offline projection.

Маршрут пилота — DirectOnly `127.0.0.1:0`, два окна на одном ПК. Новых wire opcodes, криптографии, Root доступа в runtime, зависимостей CLI/Iroh/state для desktop DTO нет. Messaging/history/intent, relay/two-device, renewal, volunteer и legacy остаются вне scope.

## Исправления после ревью реализации

- **R1.** Ошибки после spawn, включая создание и отказ reader, проходят через один финализатор с обычным Stop. После ограниченного ожидания и одной попытки завершить свой Child worker удерживает Child и Setup до наблюдённого выхода. Интерфейс показывает блокировку, отклоняет действия и ждёт завершения вне потока отрисовки. Позднее наблюдение выхода сохраняет классификацию принудительного завершения и исходную причину сбоя запуска. Штатная остановка по-прежнему требует подтверждения Shutdown, exit 0 и EOF обоих потоков.
- **R2.** Результат импорта отображается как прошедшее событие **Both locator imports were acknowledged.** Отметка подключения по-прежнему вычисляется из текущего наблюдения.
- **R3.** CLI выводит сообщение из корректного отказа runtime. Для остальных видов ответа действует прежняя строгая проверка оболочки. UI сохраняет безопасные сообщения без деталей исходного IPC.

Из 15 исходных файлов кандидата изменились `connection.rs`, его целевые тесты и `ordered2_cli.rs`. Ранее проверенные правила consent, signed locators, lease freshness, same-descriptor и повторного подключения подкреплены предыдущими receipts. Для исправлений используются отдельные целевые тесты и короткий повтор обмена в двух видимых окнах. Предыдущая матрица повторно не запускалась.
