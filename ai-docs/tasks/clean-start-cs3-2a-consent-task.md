## Reviewed contract and implementation authorization

Implement the next desktop step after saved recovery acknowledgement and frozen peer selection: create a public consent proposal using the existing own-Root CS1 CLI, exchange the file, verify/cosign on the other user, exchange the resulting finals and install both current-format contexts locally. The honest end state is “Mutual consent installed locally; connection is the next step.” A local install is not evidence that the peer imported or that any network session is active.

Root checked the actual CS1 CLI arguments/output reservation, propose/cosign preconditions, ParsedConsent2::interval/verify and admin::install idempotence in the current code (d7649d/a4989d/c05eb5). Existing install returns success without changes only when the stored certificates/accounts/membership/consent equal the supplied artifact. It does not independently enforce wall-clock expiry; the adapter must not represent an expired consent as currently usable. This task is the approved boundary contract: proceed with implementation and autonomous focused verification, not another document-only plan.

## Durable execution and failures

Use the CS3.1 isolated worker and bounded helper principles for short trusted CLI ceremonies/imports: finite per-command watchdog, concurrent capped stdout/stderr, sanitized errors, owned cancellation/reap and stale-result rejection. The CLI outputs public files; no Root secrets enter UI persistence. Factor a small reusable bounded collector if useful, not a general process framework. Keep the existing bootstrap path's protection/tests intact.

Persist per-slot artifact references/digests and outcomes in bounded public onboarding progress outside the device store. Existing CS3.1 setups must remain readable; missing new ceremony state means not started. Preserve incomplete attempts and exact successful slot state on interruption. Two slots are not an atomic transaction: never claim both installed when only one succeeded. A retry imports the identical final via existing idempotent command; no reset or changed consent to get past a conflict. Reopen validates recorded artifacts and bindings; UI flags alone do not prove repository installation. Explicit Continue/Resume may safely repeat the exact idempotent imports to establish their result after ambiguous completion.

Offline imports use own state/account/claim and occur while the messaging runtime is stopped. Handle directory-lock refusal as a recoverable user-visible conflict. All public output paths are locally assigned, outside Root/device state, no-clobber or exact-byte idempotent reuse. Do not edit CS2 ready/candidate exports to invent a fresh authority state. Reopening at each ceremony boundary must not repeat signing with different timestamps or show a false connected/ready-to-send state.
