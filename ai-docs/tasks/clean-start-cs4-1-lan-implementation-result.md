## Что реализовано

- В экране остановленного Setup можно выбрать режим на этом компьютере или LAN и задать два IPv4. Worker сохраняет явный выбор при Start. При смене выбора новый профиль создаётся отдельно, предыдущий остаётся на диске. Отсутствие LAN-поля сохраняет прежний loopback. LAN opt-in принимает только fresh Profile2 и `FreshRoute2`; общий `RouteConfig2` сохраняет прежние правила и строгую схему для Profile3/runtime7.
- Windows API сверяет один назначенный локальный IPv4 и его префикс. Runtime отклоняет адрес сети, directed broadcast и off-link peer по этому префиксу. Iroh привязывает один проверенный UDP socket. Подписанные locators и typed endpoint snapshot используют его фактический ненулевой порт. Lookup, relay и portmapper в LAN отключены. Контрольный IPC остаётся локальным TCP.
- Desktop проверяет оба подписанных локатора до записи каждого слота. Runtime сопоставляет фактический selected path с подписанными socket и endpoint при входящем и исходящем admission, до обработки authority update, на lease и перед peer commit. Status публикует selected LAN socket из успешной проверки текущего lease. При потере интерфейса новый статус убирает LAN endpoint и текущий допуск, сохраняя локальный IPC.
- Проверка ограничивает допуск приложения на выбранном пути. Iroh 1.1.0 сохраняет внутренний multipath/QNT. Для пилота нужен доверенный сегмент. Проводные форматы, модель хранилища, consent и защитная очередь сообщений сохранены.

## Остаток до полевой приёмки

Два независимых Windows-устройства с одинаковыми проверенными образами, две разные назначенные private IPv4 в общей доверенной LAN и разрешённый двусторонний UDP. На каждом устройстве участник сам создаёт аккаунт. Затем они сверяют identity, обмениваются публичными артефактами и проверяют действительный выбранный путь, сообщения в обе стороны, сохранение офлайн и доставку после перезапуска. Интернет и NAT, relay deployment, произвольные контакты, восстановление истории и volunteer storage остаются отдельными задачами.

Локальная проверка запуска использовала штатный desktop-адаптер с реальным дочерним CLI. Графическое взаимодействие с LAN-переключателем и успешный LAN admission между двумя реальными хостами проверяются в полевой приёмке.
