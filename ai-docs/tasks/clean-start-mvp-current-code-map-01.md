**Mixed/Root7 не является единственным входом в OD2.** Уже есть прямой fresh путь: `device-enroll --profile-mode ordered-dialog-v2` → indexed `RootLayout::Runtime6` → `Profile2` → `runtime-from-profile` → `Owner2`, ALPN2, новая сессия и `Guard2`, `Origin::Fresh`. Для clean-start следует сначала использовать и довести этот путь, а не создавать искусственный migration origin или переносить пустой старый профиль.

При этом **режим не выбран по умолчанию**, а desktop onboarding и основной UI подключены к прежнему runtime. «Новый аккаунт» в нынешнем desktop ещё не означает fresh OD2.

## Короткий порядок необходимых работ

1. **Зафиксировать продуктовый fresh путь Runtime6/Owner2.** Дать понятный explicit clean-start CLI entrypoint и default для *новых* workspaces, не менять формат существующей directory. Использовать имеющиеся enrollment/profile/runtime функции; автоматизировать выдачу public account/claim/device pins и случайных context IDs. Текущие два immutable slot и один peer pair — фактическое ограничение; для MVP одного диалога можно включить один из двух slots. Не обещать произвольный список чатов/группы без отдельной работы.
2. **Разнести Fresh Consent2 между двумя владельцами Root.** Предложение с credential pair, membership, context ID, сроками и `Origin::Fresh`; каждый участник видит точный peer/context, подписывает только своим Root. Cosign/verify/import используют нынешнюю проверку обеих подписей и account/device binding. Это минимальная недостающая церемония, а не задача переноса старых данных. Нужны отрицательные проверки подмены peer/context/authority/сроков/подписи.
3. **Подключить recoverable account creation к fresh indexed enrollment.** Добавить отдельный безопасный путь в bootstrap helper с прежней защитой recovery phrase/Root key и явным no-clobber. Root хранится отдельно, runtime его не загружает. Прежний bootstrap и профили сохранить; не выполнять «legacy create, затем reset/migrate» для нового пользователя.
4. **Связать desktop с Profile2 и OD2 IPC.** Небольшой явно выбранный adapter к `RuntimeIpcCommand::OrderedDialog`, существующим opcode/codec из ordered2_cli: connect/status, send с устойчивым request ID, delivery status, history cursor, locator exchange, disconnect/restart. Не fallback в legacy после ошибки. UI: создать аккаунт → принять/проверить приглашение → обменяться public Locator2 → отправить/прочитать сообщение. RouteConfig2 выбрать явно; для разных машин localhost bind из тестов недостаточен, нужны actual direct/relay paths.
5. **Небольшой clean-start acceptance для двух реальных fresh процессов.** Сначала короткий local CLI smoke, затем тот же путь через desktop, далее bounded reliability/security regressions. Не делать migration F/WholeP предварительным условием этого результата. Новые запуски — отдельная будущая task; сейчас ничего не запускалось.

Ядро уже содержит durable queue/materialize/readable/ACK и cursor history ([data.rs](E:/AI-Projects/kilogram-p2p-messenger/apps/kilogram-cli/src/ordered_dialog/runtime2/data.rs:298)), owner recovery и lease/route checks. [runtime2_process.rs:106](E:/AI-Projects/kilogram-p2p-messenger/apps/kilogram-cli/tests/runtime2_process.rs:106) показывает свежий CLI enrollment и [Pair::prepared](E:/AI-Projects/kilogram-p2p-messenger/apps/kilogram-cli/tests/runtime2_process.rs:394) — создание двух fresh peers без old-history. Это готовые основы сценария, но не новые подтверждения работоспособности на сегодняшнем HEAD.
