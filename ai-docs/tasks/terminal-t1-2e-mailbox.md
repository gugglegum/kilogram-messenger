# T1.2e. Транспорт команд полевого теста

В попытке `t12e01` отложенный ввод перестал приходить в долгоживущий SSH-процесс. Поведение воспроизвелось тестовыми строками Windows PowerShell. Новый контроллер передаёт команды короткими запросами с прежним закреплённым SSH-ключом. Один локальный PowerShell владеет дочерним терминалом и Windows Job. Его управляющий ввод поступает из каталога попытки. [Исходная попытка](terminal-t1-2e-readiness.md)

## Сессия и команды

- Host создаёт `runs/<attempt>/receipts/mailbox-<tag>` под проверенным каталогом с обычными предками. Атомарно опубликованный `owner` закрепляет generation и абсолютный Windows work tick. Для новой сессии нужен новый tag или attempt. Повторный launch с тем же tag не получает владение каталогом и не пишет квитанцию владельца.
- Короткий `submit` передаёт generation, sequence, SHA-256 и полный запрос в Base64 через сразу закрываемый stdin. Команда до 4096 байт публикуется через запись нового временного файла, flush и rename без замены. Владелец читает только готовые файлы со сгенерированным именем. Удалённые аргументы не задают путь к файлу mailbox.
- Пока текущая команда не завершилась, следующий sequence не принимается. Точный повтор принятого sequence возвращает `pending` либо `done` и доступную страницу результатов. Другие байты для того же номера отклоняются. После stop, дедлайна или закрытия без результата принятая команда остаётся `unknown`. Новая сессия не воспроизводит команды прежней. Пропавший ответ helper контроллер может один раз запросить с теми же байтами; он прекращает полевой сценарий, если исход остаётся неизвестным.

## Публичный поток и завершение

- У Setup в outbox попадают строки из прежнего разрешительного фильтра. Этот мост перенаправляет все потоки с запуска, обрабатывает recovery внутри хоста и публикует только безопасный ответ. Chat передаёт существующие JSONL ready/result/incoming, коррелирует результат с ожидаемым ID и сохраняет incoming в порядке чтения stdout. Команды обоих терминалов проходят одним и тем же коротким каналом.
- Записи outbox пронумерованы с 1. Read с cursor возвращает до восьми следующих записей. Повтор чтения с тем же cursor возвращает уже опубликованные записи. Контроллер сохраняет последний принятый cursor и учитывает каждую запись один раз. Сессия ограничена 192 командами и 512 публичными записями размером до 16 КиБ каждая.
- Штатное закрытие требует подтверждённого результата `quit`, кода выхода 0, EOF и пустого Job. После подтверждения `quit` владелец закрывает приём новых команд. `stop` публикует маркер для владельца и сохраняет отдельный результат завершения даже при EOF. Локальный watchdog оставляет резерв на уборку и сохраняет абсолютный срок после потери контроллера. Принудительная уборка оставляет нештатную квитанцию.

Стенд проверки опирается на отдельные свежие каталоги и PowerShell-имитатор. Файлы первой попытки и установленные бинарники D.2 остаются в своих каталогах. Физический повтор Setup → chat проводится после review этого транспорта.

## Локальная квалификация

`mb-local04` прошёл с задержками первой и второй команды на 3 и 18 секунд. Имитатор обработал точный повтор только один раз, а outbox вернул `incoming` в исходном порядке при повторном чтении с прежним cursor. Конфликт хешей, неверный generation, пропущенный sequence, переполнение и неполный ввод отклонены. Уход контроллера оставил отправленную команду в состоянии `unknown`. Watchdog завершил дочерний Job. ## Проверка на ноутбуке

`mb-remote04` прошёл на `PAUL_HP_OMEN` под закреплённым SSH. На ноутбуке сверены SHA-256 пяти скриптов в новом тестовом каталоге. Публичный имитатор принял обе отложенные команды, вернул прежний результат точного повтора и сохранил порядок `incoming`. Штатный `quit` записал код 0, EOF и пустой Job. В отдельном тесте контроллер оборвал свой SSH-запуск при активном имитаторе. Watchdog завершил дочерние процессы по лимиту. Повтор принятой команды вернул `unknown`, а квитанция показала принудительное завершение и пустой Job. Ноутбук запускал только публичный имитатор.
