# T1.2c. Результат реализации и проверок

База `52200d9169a1c543a3047aac41b4c3baca48652a`. Терминал готовит два публичных предложения, принимает их для подписи, принимает подписанный final и повторно проверяет оба локальных импорта. Каноническая роль определяется по `device_id`. TTY и JSONL используют один слот с pairing и consent preview. Inspect сверяет тип, привязки, оба payload, lineage, сроки и занятые локальные пути без записи. Accept потребляет сохранённый объект и повторяет проверку под Setup lock. [Контракт](terminal-t1-2c-contract.md) · [Общий адаптер согласия](../../crates/kilogram-first-dialog/src/consent.rs#L567) · [Терминальный адаптер](../../apps/kilogram-cli/src/terminal_setup/service/agreement.rs)

Writer проверяет период перед сериализацией снимка. На границе срока пропадает текущая отметка установки, а оба записанных результата импорта сохраняются. Принятая отмена сбрасывает подтверждение текущего сеанса. При неподтверждённом завершении helper сессия закрывается даже после сбоя записи `Failed`. Существующие GUI API, форматы обмена и durable запись Setup сохранены. ## Проверки Windows

- `build03` сверил CLI и bootstrap после offline locked сборки с Idle и одним заданием. SHA-256 CLI `4146d87b549dd79b0daf8bc50280ad84da9a64a942319310901c9dec856ae441`. SHA-256 bootstrap `c1b44ee7550caf32978aa9c279ae911d443702ac3c386c4519b1ed3d43def6be`. Образы сохранены в архиве кандидата.
- `smoke04` проверил штатные локальные команды без fixture в обоих порядках канонических ролей. Проверены TTY reopen и import, JSONL workflow, замена proposal/final после inspect, чужие ID и контексты, перепутанные payload, отказ подтверждения, общий preview, no-clobber и reparse. Для обоих порядков измерена фактическая установка в каждой базе. При конфликте `import-1.context` установлен только слот 0, а Setup показывает `accepted, failed`. После reopen и точного повтора установлен слот 1, поколение увеличилось на один. Следующий повтор сохранил поколение. Захват recovery выполнялся в памяти и очищался. [Квитанция сквозного сценария](../../.tmp/terminal-t1-2c/native04/evidence.json)
- `cli03` прошёл 11 целевых тестов. Детерминированная проверка использовала один снимок до и точно на границе истечения срока в обеих формах вывода. Проверены необходимость подтверждения, буквальные пути, отмена до завершения, приоритет `cleanup_unconfirmed` и блокировка следующей команды при проблемах writer.
- `shared03` прошёл 6 записей фильтра `consent::tests::`. В том числе реальные проверки ролей, восстановления `started` после коммита без ответа и идемпотентности, отказов на двух payload и сохранения ошибки helper при сбое записи `Failed`. Две записи поддерживают опциональные тестовые сценарии. Снятие поколения на терминальных копиях выполнялось отдельным запуском одного теста из стабильного harness.

Квитанции и stdout/stderr ранних прогонов сохранены. `build01`, `build02`, `cli02` и `shared02` имели exit 0 дочернего процесса, после которого обёртка обнаружила и завершила остаточный `vctip` в своём Job. `cli01` остановился до сборки на неподходящем параметре каталога стабильных EXE. В `smoke01` и `smoke02` исправлены сравнение канонического Windows-пути и форма поля device в тестовых данных. `smoke03` сравнивал физические байты Redb после повтора. `smoke04` проверяет поколение репозитория и установку каждого слота.

Сборка T1.2c повторно использовала стабильный терминальный путь. По нему теперь лежит новый CLI.
