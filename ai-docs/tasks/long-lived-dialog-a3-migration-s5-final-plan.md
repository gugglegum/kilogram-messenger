## 2. Выявленные prerequisites для реализации

1. **Два genuine C без setup Text.** Old `runtime.rs::established` вызывает `handshake_a` после admission независимо от queue, поэтому оба enrolled contexts могут завершить Ready/genesis при C1/C2 Text=0. Нужны два context-create/import, оба C в old profiles, actual signed locator imports каждого C и assertions complete phase3/next1/1/SID. Только затем8 rounds C1 A2/B2. Отсутствие C2 Ready нельзя компенсировать лишним warm Text.
2. **Queue17/18 при остановленном B.** Old `runtime.rs::data_worker` материализует только в admitted connection loop (`materialize_one`), а локальный `ordered queue` сохраняет запрос отдельно. Stop B, actual wait/exit и observed A connection backoff; затем queue17/18, убедиться в неизменных source frontier/native_generation и двух exact accepted requests через bounded stopped source/queue view перед migration. Stop A перед exclusive storage-upgrade. Нельзя просто надеяться, что kill опередил materialization. Не давать frozen d9b новые debug fields, которых не было в его сборке.
3. **Сохранение исходного gap/debt.** Old B удерживает committed B16, у A suspend-prefix; B17..24 после обновления A дают pending, не readable gap-fill. A17..23 должны получить настоящие receipts до включения ACK hold. До A24 включить A-side query suppression и B-side push hold, чтобы actual saved B Receipt1(A24) существовал, но ещё не был принят A. У frozen old path disable_ack подавляет push; сам по себе он не доказывает подавление всех queries. При current A одновременно использовать действующий `protocol.rs::ack_query` gate. В pre-Q записать actual debt+receipt association, затем принять **этот** R1 до Q и подтвердить ровно одно retirement; не фабриковать receipt или снимать debt по Head.
4. **No early upgrade.** До необходимого handoff не импортировать current existing Consent2/Locator2 и не создавать UpgradeIntent. Consent1/membership/authority должны оставаться current для old interop и C2; public existing-origin/Consent2 propose+cosign делают только после настоящей Ready каждого C. Привязка current policy/lease проверяется до/после критического IO, не только после import.
5. **Mixed long ordinals не проходят нынешний OD1 scheduler.** `test_support.rs::load` требует `hold_ordinals <512`; нельзя передать ему B640. Новый узкий debug-only Runtime7 verification control (`KILOGRAM_TEST_S54_SCHEDULE`, outside-state/capped/deny_unknown_fields) отделяет mixed holds от frozen/OD1 parser; default отсутствия hooks должен сохранять старый путь. Удержание B640 на direct delivery требует также запретить у A C1 prefix requests, иначе Head выдаст B640 через prefix reply, который сейчас не проверяет `Schedule::held`. Снять оба ограничения только при relay continuation.
6. **Runtime7 не имеет S4 full64/page/ACK hooks.** `runtime7::protocol2::outgoing2/prefix_reply2` держат собственные RefPermit2, cap16 items; `accept_prefix2` сохраняет page, но не считает/не сигнализирует page2/5. S4 `runtime2/hooks.rs` не вызывается Runtime7 и несовместим по schedule schema. Нужны локальные S54 observations: after successful durable page acceptance + Owner reply; before actual nonempty ACK write; live delivery suppression при переходе на prefix-only repair; actual retained source-selection64. Нельзя тормозить Owner7 синхронным барьером на время C2 progress.
7. **64 refs — реальные64 distinct undelivered IDs, а не padding.** Предлагается narrow debug source-selection в network2 перед outgoing: под Owner7 прочитать64 настоящих C1 debt refs (ровно две bounded `L1Repository::debt_page` по32 с actual `after`, затем проверить immutable event associations), удержать их в bounded Vec и **реальный** `RefWindow2::reserve(C1,64)` вне Owner вместе с этими64 IDs. Async hook приостанавливает эту selection до release, не меняя source/queue/debt/Native и не увеличивая wire page16. Счётчик64 должен соответствовать64 distinct actual IDs; отсутствие64 debt refs — отказ, не dummy reserve. Для P5 выбирать удерживаемые successor refs после A385 и до C2, при B ordinary_pending64. Это **новая проверочная selection**, не утверждение, что штатный одиночный Runtime7 RPC уже содержит64 refs. Block1 source review и короткий real-process check обязаны подтвердить смысл/достижимость такого hook до whole P; две консервативные reservations32 без64 actual refs не подходят.
8. **Counters, guard facts и смерть процесса.** Runtime7 Stats7 имеет actual committed_encrypt/decrypt/attempts/aborted/constructors, но stats обнуляются при новом Owner, а status.native содержит keys/SID/next без peer_g. Добавить debug public observations guard.g/index/first/rotate_due и PID/incarnation-scoped packet commit/attempt records с последующим actual state reconciliation. При kills на network barriers Owner должен оставаться доступен для снимка counters; evidence после durable commit не должно теряться из-за hook до stats update. Не вычитать два snapshots разных PID, не складывать повторно cumulative snapshots одного PID. Ambiguous IO/потерянный terminal snapshot требуют source/outcome resolution, а не предполагаемого нуля.
9. **Current wrappers пока не принимают P5.** S53 outer разрешает только `[CF]-s53-*`; `Managed::new` hardcodes старый baseline `64c235...` и `.tmp/migration-s53-integrated`. Это реальные fences, не P5 API. Добавить отдельный точный P-s54 case/admission branch с baseline20418e41 и новым owned attempt path, сохраняя старые clauses без bypass. Использовать прежние inventory/envelope/deadline/frozen helpers; один тонкий S54 case/outer adapter допустим, новая иерархия runner/preparation revisions — нет. Не подставлять P5 под старый C/F case.
10. **Маршрут задаётся существующим Profile3, отдельного route3-configure CLI нет.** Reviewed `handoff::route` меняет bounded public `Profile3.route` при stopped owner; `Profile3::load/route_config` и runtime проверяют effective route/eligible modes. Переиспользовать этот точный способ с сохранением config identity/published fields, затем `runtime-from-profile` и signed Locator2 import. Не придумывать новый operator command или обход authenticated capacity publication. Original keys/Native/queue witnesses требуют trusted bounded oracle на **новых** P5 states/source backing: old status даёт SID/generations/frontiers, не все SessionKeys; перенос key equality не выводить только из SID. Реализовать сравнение через принятые source/migration и Native-open seams, с in-memory equality и только fingerprints наружу.

Это gaps проверочного controller/infrastructure, не установленный дефект принятого протокола. До их реализации и review нельзя считать P5 runtime-ready. Product wire, writers, permissions, budgets, crypto и deadlines менять ради теста не предлагается.

Root administration dirs этих новых участников остаются отдельными; дополнительный C не означает третьего runtime. Temporary migration source backing остаётся положенным storage-upgrade immutable witness, а не второй writable Native branch.

## 4. Cardinalities и observation contract

- C1:16 old Text/side +8 compat/side =24/24. От handoff до финала616 new Text/side; это1232 format2 Text. C2:32/32 legacy Text, handoff без новых Text. Итого1280+64=**1344 Text**, плюс две genesis/C =**4 genesis**. Участники сохраняют original sessions; четыре Native Account и четыре Session constructor origin effects соответствуют2 C×2 roles, не четырём пользовательским enrollment accounts.
- Post-B25 continuation: `25+16×32−1=536` unique B Text; вычитание1 — retry25, а не пропуск нового сообщения. A `24+16×2=56`; A57..384 даёт328, offline385..640 ещё256; B537..640 даёт104. Request IDs/expected bodies задаются чистой функцией `(C,role,text-number)`, retries используют exact прежний ID/body, а не формируют новые.
- Normative successful operations: `(1344+4)×2=**2696**`. Frozen CLI не выдаёт S4 numeric call logs: old accepted effects выводятся из настоящих signed sources/readable prefixes/genesis, а actual новые current packet operations берутся из per-incarnation counters/commit records. На старом setup8 genesis ops +32 encrypt+31 decrypt =**71**. Compat добавляет16 encrypt+8 decrypt =**95**. Девять delayed old decrypt дают **104 old/genesis subtotal**. Это **не** общий live counter после B25: хронологически B25 encrypt добавляет1 до repair, old repair9 и B25 decrypt1 дают106 к early-readable boundary. Остальная ledger-классификация format2 C1=1232×2=2464 и C2 Text=64×2=128;104+2464+128=2696. Эти множества не пересекаются, B25 входит в2464 ровно один раз.
- Copy/handoff constructors/packet calls0; exact generation bump соответствует conversion, не retry. Actual new process counters суммируются по PID/incarnation и committed operation identity; attempts/aborts/ambiguous учитываются отдельно. Reopen/deserialization не названы packet operations. Проверка stopped source/projection/request/receipt связей дополняет, а не заменяет counter evidence.
- Main final artifact: один envelope с source/image/inventory identity, phase summaries, original/final associations, counters, native marker; плюс обычные logs/case/outer receipts. Частные keys/Native/DB bytes не экспортируются; использовать существующий `public_fingerprints` перед каждым JSON/log write, сохранять equality/короткие public digests. Внутренний status с `native.keys` не печатать целиком из CLI stdout в публичный packet.
- RAM: sampled profile PrivateBytes<=384MiB, existing redb/cache/owned-buffer caps, native<=128KiB, bounded commit app buffers и resource limits по прежним assertions. Периодические samples — не доказанный unsampled peak. Memory shell входит в runtime dependency inventory; native side-channel bound и job cleanup не подменяют actual functional result.
