## IPC и смысл текущего состояния

Client загружает bounded descriptor≤16KiB один раз, проверяет нынешние signature/version/token/loopback address и expected account/device **в том же объекте, из которого берёт address/token**. У `load_descriptor` сейчас metadata check + `fs::read`; при выделении общей функции ограничить сам read через take(cap+1), чтобы рост файла не обходил cap. Descriptor, bearer token, local claim и пути не экспортируются; client Debug/errors их не печатает. Замена descriptor на диске не переключает работающий client на другой сервер.

OD2 requests сохраняют `[2,opcode,…]`: status `[2,1]`, import `[2,5,slot,raw]`, export `[2,6,slot]`; replies ровно `[2,same_opcode,result]` внутри `RuntimeIpcResponse::OrderedDialog`. Status result — bytes JSON≤48KiB; export — bytes≤8192; import — **пустой массив**, без echoed context; Shutdown — только `ShutdownAccepted`. Outer kind/Error, nested length/version/opcode/тип/cap проверяются до проекции. Для OD2 ограничить outer framing64KiB до allocation, сохранив прежний generic IPC cap256KiB. Legacy mode в descriptor отсутствует: его отсекает первый обязательный valid OD2 status, без Ping/fallback и без Shutdown до подтверждения owned OD2. Вся операция≤5s через отменяемый timeout поверх прежних transport timeouts.

Status DTO отражает **настоящие** две формы producer: неустановленный slot имеет `{slot,installed:false,active:false,publication_ready:false,counts}` без context/phase; установленный **не содержит `installed:true`**, но имеет context/role/phase/active, d/e/sid/q, blocked, revisions, publication_ready/file_exported/policy_error, native_generation/counts/details. Проверять exact slots0/1, unique/context order и canonical role; у Active2 обязательны phase3 и заполненные d/e/sid/q. Top-level version2, contexts, endpoint, route, root_generation; `details.current_consent` — typed canonical ID, остальные известные diagnostics (stats/window/resources/backend/counts и прочие details) можно bounded consume через `IgnoredAny`, они не источник authority. Никаких assumed `connected`, строкового `phase=Active2` или обязательного `installed:true`.

Новые status fields: `runtime_pid==Child.id()` при живом owned handle до/после запроса; `runtime_instance` совпадает с первым принятым status этого запуска. `live_admitted` true только после successful current policy и Lease2::check; `lease_expires` — соответствующий wall deadline, иначе null. Проверка уже связывает selected route/TLS endpoint, locator IDs, policy generation, valid flag, mono/wall deadlines и close_reason. Producer active по-прежнему означает две сохранённые Ready; это не новая трактовка существующего поля.

Connected по slot: **fresh successful status + owned child alive + phase3/active + live_admitted + unexpired lease + blocked=null + policy_error=null**, exact selected context/role/route/consent binding (current_consent из details совпадает с retained final reference). Это наблюдение проверенной runtime lease на момент status, не гарантия непрерывной доступности между наблюдениями. Общий badge требует оба slots; UI может отдельно показывать progress каждого. Publication_ready/успешный import/Sync2/IPC reachable/phase3/исторический active отдельно connected не включают. Poll1Hz, максимум один запрос вообще на connection worker; user action приоритетнее, ticks coalesce. Freshness2s считается от monotonic **начала** status request, не от получения reply; ответ уже старше2s badge не оживляет. Run/action generation и request-start сохраняются, старые replies после queued action/stop игнорируются. После error/child exit/stop badge убрать сразу; без свежего результата или по consent/lease expiry — stale на каждом кадре, даже пока 5s IPC ещё ожидается. Отменённые/старые generation результаты не применяются. Скрытая/pause UI не poll/start: pause завершает owned runtime.

## Public Locator2 exchange

[ParsedRuntimeLocator2](E:/AI-Projects/kilogram-p2p-messenger/crates/kilogram-protocol/src/ordered_dialog_v2/runtime_locator.rs:76) уже проверяет десятипольное body/signature, context и ordered cert refs. Descriptor cap8192,≤16 sorted unique IPs, nonzero ports, revision>0, interval nb<expires; relay URL≤2048 canonical HTTPS либо HTTP-loopback. Сам `verify` не проверяет wall time/revision/route: их применяет [Owner2::import_locator](E:/AI-Projects/kilogram-p2p-messenger/apps/kilogram-cli/src/ordered_dialog/runtime2/owner.rs:824). Меньшая revision и same-revision/different-bytes — отказ; byte-identical retry идемпотентен. [rotate_locator](E:/AI-Projects/kilogram-p2p-messenger/apps/kilogram-cli/src/ordered_dialog/runtime2/owner.rs:701) повышает revision, подписывает текущий endpoint, срок сейчас1час; restart обновляет instance/locators. Не обещать автоматическое peer-обновление при истечении.

Новый отдельный strict `locators` envelope: `{version:1,kind:"locators",profile_mode:"ordered-dialog-v2",invitation,contexts:[C0,C1],sender:{account,device},recipient:{account,device},locators:[hex0,hex1]}`. Sender/recipient — **только** frozen IDs; credentials/floors уже есть в setup. Ни старые invite/reply, ни consent envelope не расширять. Whole file≤48KiB; ровно два blobs≤8192 каждый (canonical lowercase hex≤16384), ID fields exact64, unknown/duplicate/trailing/future отказ; aggregate проверяется до hex allocation. Worst case двух hex blobs32768 + фиксированные поля/IDs <48KiB.

Export: оба IPC6 результата проверить существующим parser/verify относительно own/peer frozen credentials и ordered contexts, interval, одинакового текущего endpoint из status и pilot route, затем экспорт no-clobber. Endpoint/revision повторно сверить с текущим status перед публикацией; при гонке вернуть recoverable refresh, не публиковать частичную пару. Только signed public bytes уходят peer. Public runtime `.locator` filenames и IPC descriptor не являются обменным файлом. После restart прежний envelope отмечается старым, новый export получает новые locators, прежние bytes сохраняются.

Import: freeze entire candidate, проверить **оба** blobs/bindings/signatures/interval до IPC5, sender==peer/recipient==own, одинаковый peer endpoint, pilot DirectOnly; в этом UI все IP loopback, relay отсутствует. `RouteConfig2::remote` сам не ограничивает remote IP loopback, поэтому ограничение локального пилота явно проверяется адаптером, без расширения transport. Предварительно сравнить revisions с текущим status; равную revision без знания retained raw не объявлять совпадением — окончательно решает прежний owner. Затем два отдельных IPC5, сохранять Started/Accepted/Failed по slot и digest retained envelope. Ack не содержит context: привязка — typed slot request + frozen raw + matching opcode; status/export сверяют context там, где он реально есть. Не выдавать ack/revisions за доказательство exact peer import или connectivity.

Если slot0 принят, slot1 отказал/timeout — Partial/Ambiguous, связь не объявлять общей; explicit retry тех же bytes через idempotent imports. Более новый peer envelope можно явно выбрать после проверки обоих, предыдущие файлы/исходы сохраняются. Истёкшее/повреждённое/wrong-peer input не заменяет прежнее retained selection. После reconnect старый peer locator может остаться в store, но это не current connection proof: роль0 сама dial, роль1 listen ([runtime loops](E:/AI-Projects/kilogram-p2p-messenger/apps/kilogram-cli/src/ordered_dialog/runtime2/runtime.rs:1081)); отдельного Connect/Sync2 шага нет.

## Owned lifecycle и состояния UI

Runtime — фиксированный trusted `target/clean-start-runtime/kilogram-cli.exe`, typed `runtime-from-profile --profile-file LOCAL`; hashes проверять по содержимому. Owned worker удерживает `Setup`/UI lock и Child handle; постоянный runtime не запускать через 60s one-shot collector. Переиспользовать его owned wait/cancel механизмы, но drains работают всю жизнь процесса: фиксированные ring buffers≤64KiB stdout/stderr, overflow отбрасывается с counter, без роста/логирования private output. Ожидание не в render thread. Не применять legacy profile editor/watcher/launch.

В `Record` добавить optional bounded `connection` version1: ограниченная относительная ссылка/digest выбранного profile, ссылка/digest последнего locator envelope, два исхода импорта (прежний Outcome), последний sanitized lifecycle outcome. Сохранять через нынешний atomic update; отсутствие поля совместимо со старым setup. Runtime/client/PID ownership, generation, свежесть и connected — **только в памяти**. Retained Started после crash означает ambiguous; файл и acknowledgement сами по себе не дают success. После таймаута отмена IPC не отменяет уже принятый runtime commit: повторять exact raw, не генерировать новые locator bytes от имени peer.
