## Binding amendments

1. **Use the existing byte-budgeted history pages instead of forcing one row.** Request up to 32 rows; validate at most the requested count, strict row fields and the actual JSON/frame caps. `history_read_bounded` already measures each serialized row before advancing its cursor and returns a shorter page if the next row would exceed the byte budget. The existing `a3_s4_component_ipc_history_escaped_byte_budget_no_cursor_skip` test requests 32 and expects one maximally escaped row per returned page. Two maximal escaped messages not fitting a frame is therefore not a reason to force every ordinary page to one message. Keep the bounded 32-row visible window, explicit page navigation and one page per worker action; no new pagination protocol, unbounded scan or auto-drain is required. Test both multiple short rows in one page and forced byte-limited splitting with exact completeness/no duplicates. Starting at the beginning and manual refresh remain pilot limitations, not the final everyday-chat experience.
2. **Make the DTO and scheduling bounds agree with that choice.** Replace all limit1-only assumptions in the proposal, schema validation and matrix. Cursor must advance on a nonempty continuation, view/frontiers remain bound, and a short page is not EOF unless finished is true. Include actual framed maximum escaped text and a mixed page in the focused tests. Retain bounded/coalesced UI actions, regular status priority and cancellation priority; a slow background lookup must not make a stale network badge appear current.
3. **Split acceptance/publication as well as implementation.** CS3.3a is the typed IPC plus protected send lifecycle/worker seam and focused tests. Submit that coherent slice for review before commit/push. CS3.3b adds the composer/history presentation and actual dual-UI acceptance after CS3.3a is accepted and published. Do not silently implement both before a single combined review. Keep the later GUI matrix in the contract but mark it deferred to CS3.3b.

## CS3.3a scope

- Add typed op2/3/4 methods to the existing verified-descriptor Client2, strict bounded DTOs, and the small exact safe-error classification needed by the lifecycle. Preserve existing CLI diagnostics and status/locator/shutdown semantics. Do not log plaintext, tokens, cursors or raw error payloads through derived Debug/error chains.
- Implement the protected local intent adapter and lifecycle within the existing owned worker boundary. No new send control is exposed until the full safe path is ready. Separate small intent/state-machine concerns from the already large connection module where it improves reviewability; avoid unrelated architectural refactoring.
- Cover publish-before-dispatch, actual runtime commit before ignored/lost reply, reopening the same protected record, positive lookup suppressing op2, explicit retry after fresh Absent, exact-byte/idempotent conflict behavior, Accepted-to-Absent, and failed persistence/cleanup. Use small deterministic seams for injected failures and existing fresh runtime helpers for real wire/durable-store behavior; clearly distinguish simulated fault boundaries from actual process exits.
- Verify actual Windows DPAPI round-trip, corrupt/wrong-binding/oversize/staging cases and absence of the synthetic plaintext sentinel in the adapter's ordinary persistence/log outputs. Never treat the intentional test source constant as a leak or print sensitive test payloads into evidence. Same-user checks are not a different-user isolation test.
- Test the revised history batching, caps and cursor behavior via real fixed-path runtime IPC plus focused parser negatives. Preserve unchanged earlier tests/evidence rather than rerunning broad migration/endurance campaigns.
