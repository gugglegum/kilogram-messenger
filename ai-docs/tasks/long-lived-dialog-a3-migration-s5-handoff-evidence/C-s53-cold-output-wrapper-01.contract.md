## Proposed minimum behavior

Retain reflection and all existing exact type, signature, delegate and hash checks; remove `$consumed` and the exception-chain entry guess. Do not add a reflection adapter, callback proxy, retry or raw-handle close.

The wrapper is a one-use binding transaction on an exclusively owned, fresh Core, before its first CaptureAndCompare, with no concurrent/reentrant Core or owner use. Existing small callers meet this ordering. Before TakeDirectory, read the existing observation and reject known non-fresh state: remaining/peak filesystem handles, hash passes/bytes, capture timestamp and receipt bytes zero; Completed, ExpectedSetCapturedBeforeHash, InputHandlesReleased and ReceiptsCompleted false; FailureCode null and CleanupUnknown false. Constructor scratch/record allocation is allowed. These observations are a defensive rejection filter, **not** proof against concurrent or reentrant use: reviewed caller provenance and exclusive fresh-object ownership remain prerequisites. Already-bound, captured, failed or disposed Core must be rejected before taking E; do not destroy it. No support for binding after capture is introduced.

Allocate the five-slot arguments array and acquire/check delegates before TakeDirectory. Immediately protect successful TakeDirectory with the failure-cleanup scope, including assignment into arguments. A TakeDirectory refusal leaves Core and output owner with the caller. After TakeDirectory succeeds, any wrapper/invocation failure terminates this new transaction; no rebind or retry. The caller must not continue using that Core even if native entry cannot be established.

| Boundary | Sole responsibility |
| --- | --- |
| Before successful TakeDirectory | Caller owns Core; owner owns E plus six retained ancestors. Validation refuses without disposing either. |
| After TakeDirectory, before Core accepts | Wrapper holds the sole pending E wrapper; owner retains six ancestors and truthful transferred state. |
| Normal BindOwnedOutput return | Core owns E; wrapper clears only its local references. Caller later disposes Core, then owner. |
| In-Core refusal | BindOwnedOutput's finally consumes incoming E; Core records failure/close facts. Wrapper still follows the same failure cleanup, independent of exception shape. |
| Entry or transfer uncertain | Wrapper disposes Core first, then disposes pending only if still open. Caller disposes owner/fixture resources separately. |

Core-first order matters: a late failure can occur after assigning outputDirectory, including StopPhase. An open pending wrapper alone cannot establish pre-entry ownership. Core.Dispose first releases any Core-held output; only then is an open pending wrapper a managed fallback. Fresh-only admission prevents this failure policy from destroying a valid earlier captured/bound transaction. Core.Dispose is idempotent; existing caller finally may invoke it again. Output-owner Dispose never closes E after TakeDirectory and must still close its own ancestors. Do not reset owner transfer flags, restore E ACLs or delete evidence.

Capture the original ErrorRecord immediately. Before cleanup, capture bounded primitive facts: incoming IsClosed/IsInvalid; Core failure classification, remaining handles, CleanupUnknown/native error. Record Core.Dispose completion/exception, post-Core facts, whether fallback was needed, and resulting managed wrapper state. Keep the first secondary exception type/HResult and uncertainty flags as bounded primitive Exception.Data diagnostics; no raw handles, replacement exception, extra pipeline output or unbounded exception serialization. Each observation/cleanup/diagnostic attachment is guarded so its failure cannot replace the original record. Finish by rethrowing that saved ErrorRecord via `$PSCmdlet.ThrowTerminatingError($primary)`; caller verifies original Core and private_acl marks/HResult, rather than requiring an invariant outer PowerShell wrapper. [Microsoft's ErrorRecord guidance](https://learn.microsoft.com/en-us/dotnet/api/system.management.automation.cmdlet.throwterminatingerror?view=powershellsdk-7.4.0) supports preserving additional error information this way.

A closed SafeFileHandle is a managed-state observation, not native-close success. Core CloseFile explicitly calls CloseHandle and invalidates the wrapper even on failure; preserve its CleanupUnknown, CleanupNativeError and nonzero accounting. Never retry an uncertain native close or call DangerousGetHandle for wrapper cleanup. Managed fallback Dispose does not supply an independently observed native result: report fallback/native-close status unknown conservatively. A cleanup throw, failed observation or contradictory accounting also fails cleanup acceptance without replacing the primary cause. No fallback and no cleanup exception are expected in the two normal focused cases; fault-injected cleanup correctness remains source-reviewed only.
