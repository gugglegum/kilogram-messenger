# T1.1d. Обмен публичными локаторами из терминала

Предложение для архитектурной проверки на базе `7836b1f6d4a30e05cf727605a29bbf7542dd18d2`. Два готовых Setup должны установить и восстановить соединение командами терминала. В пользовательском сценарии обмена нужны только два терминала и передача между ними публичных файлов. Полевой LAN, onboarding, входящие уведомления и итоговый двухкомпьютерный пилот относятся к следующим этапам. [Контракт T1](terminal-t1-contract.md) · [Отмена и завершение T1.1c](terminal-t1-1c-contract.md)

## Что подтверждает текущий сервис

GUI отправляет `Action::Export`, `Import` и `Resume` через `Work`. Ответы видны как текст `View`. `Session` уже получает локаторы двух слотов у закреплённого runtime, проверяет экспорт по текущим endpoint и ревизиям, сохраняет входной файл и записывает прогресс каждого слота. `locator_artifact::Envelope` проверяет отправителя и получателя по account/device, приглашение, порядок контекстов, подписи, срок действия, общий endpoint и допустимый маршрут. Импорт с меньшей ревизией отклоняется. При равной ревизии runtime подтверждает только те же подписанные байты. Точный повтор подтверждается без новой записи. Ревизия из status сама по себе не удостоверяет байты или текущую связь. ## Команды и файлы

| TTY | JSONL v1 | Результат |
| --- | --- | --- |
| `/locator export` | `locator_export({})` | Новый публичный bundle обоих контекстов текущего владельца. |
| `/locator import <путь>` | `locator_import({"path":"…"})` | Проверка и импорт двух слотов из указанного файла. |
| `/locator retry` | `locator_retry({})` | Повтор сохранённого bundle с проверкой прежнего digest. |

Действия доступны в `connect start` и охватывают оба контекста независимо от `/use`. `connect attach` возвращает `observer_read_only` до чтения файла, записи или IPC. Без подключения применяется `not_connected`. В TTY хвост после одного разделителя передаётся целиком как путь, включая пробелы и Unicode. Кавычки и обратные слеши в TTY считаются буквальными символами. JSONL принимает строку пути с обычным JSON-экранированием. Относительный путь отсчитывается от рабочего каталога запуска CLI. Пустой путь и NUL отклоняются. Help показывает синтаксис и пример пути с пробелами без кавычек.

Экспорт использует штатный каталог `<Setup>/connection` и новое имя `public-<id>.json`. Путь возвращается в результате; для TTY вывод экранирует управляющие символы. Запись через `model::write(..., false)` не заменяет файл при коллизии. В JSONL передаётся путь, а содержимое переносится отдельно пользователем. Артефакт содержит только поля существующего публичного envelope и подписанные локаторы. Descriptor, bearer token, claim и ключи остаются за пределами экспорта.

Вход читается штатным ограниченным reader как обычный файл размером до 48 КиБ. Копия валидного входа сохраняется под `peer-<digest>.json` в каталоге Setup. Существующий файл с этим именем принимается только при совпадении байтов. Для файлов внутри `connection` используются проверки канонического каталога, reparse points и границ приватного состояния. Исходник импорта не меняется. TTY и JSONL получают безопасные коды и структурированные поля, без содержимого ошибочного файла. [Пути](../../crates/kilogram-first-dialog/src/connection.rs#L130) · [Чтение и запись](../../crates/kilogram-first-dialog/src/model.rs#L16)

## Общий результат и безопасный повтор

Добавить один тип результата локаторов к существующей очереди `Work`. Терминальный запрос получает типизированный reply с привязкой к поколению команды и текущему scope. GUI использует те же операции `Session` и отображает их результаты в существующем `View`. Сохранить валидаторы и штатный `Client2`. Новые команды включить в terminal help и таблицу T1. Бюджет одной операции — 30 с с учётом вложенных ожиданий.

- Экспорт возвращает `exported` с `path` только после успешной публикации проверенного bundle. Ошибку готовности обозначает `locator_unavailable`.
- Импорт и retry возвращают `imported` после двух проверенных ACK текущей операции и подтверждённой записи прогресса. После частичного или неопределённого результата возвращаются `partial` или `unconfirmed`, digest, если он известен, и два слота. `retained:true` подтверждает выбор этого digest в Setup, при неизвестном результате выбора возвращается `null`. У слота есть состояние попытки (`confirmed`, `unconfirmed`, `not_attempted`) и бит сохранённого подтверждения для того же digest. Если IPC подтвердил оба слота, а сохранение прогресса осталось неопределённым, общий результат остаётся `unconfirmed`. Ошибки до начала изменений возвращают `ok:false` с кодом, например `invalid_locator_bundle`, `stale_locator_bundle`, `no_retained_locator` или `retained_locator_changed`.
- Один раз прочитать исходные байты, проверить оба слота и использовать тот же буфер для копии и IPC. При retry в этот же путь передавать буфер, уже сверенный с сохранённым digest. Сейчас `Resume` после проверки повторно открывает путь через `Session::import`. Прямой вызов общего импорта проверенных байтов убирает расхождение. Сегодня повтор переписывает `Accepted` в `Started` перед вызовом IPC. При повторе того же digest сохранить прежнее подтверждение при обрыве. Повторить точные байты обоих слотов и подтвердить состояние заново для текущего instance. При явном импорте другого прошедшего предварительную проверку digest сначала записать его как выбранный bundle, затем вести прогресс для него. Старые файлы остаются на диске. [Входной bundle и прогресс](../../crates/kilogram-first-dialog/src/connection.rs#L726) · [Существующий Resume](../../crates/kilogram-first-dialog/src/connection.rs#L1116)

Импорт даёт результат локальной установки. После него клиент отдельно проверяет `status.live_admitted`, которое требует текущей аутентифицированной связи для обоих контекстов. После рестарта сверить новый `runtime_instance` и заново обменяться свежими экспортами. Retry использует прежние байты и может подтвердить их локальную установку даже тогда, когда для удалённого endpoint уже нужен свежий bundle. [Текущий status владельца](../../crates/kilogram-first-dialog/src/chat.rs#L149)

## Отмена

Достаточно снимка результата локаторов в существующем `OperationControl`. Допуск к первой записи, включая возможное создание каталога, и допуск к IPC каждого слота защищены тем же замком, где принимается cancel. До первого допуска `cancelled` подтверждает отсутствие записи и импорта этой попытки. После допуска к публикации экспорт может вернуть `unconfirmed` с уже выбранным `path`. Путь сам по себе не подтверждает, что файл опубликован. Успешное завершение записи до фиксации финала даёт `exported`.

При отмене импорта после начала сохранения или IPC снимок сохраняет уже подтверждённый digest и статусы слотов. Начатый импорт без проверенного ответа остаётся `unconfirmed`; второй слот без допуска остаётся `not_attempted`. Штатную запись полученного ACK завершает тот же worker. Итог не откатывает принятый слот и не удаляет выбранный файл. Если выбор bundle подтверждён, следующая команда `/locator retry` использует его точные байты. Пока выбор не подтверждён, клиент повторяет явный импорт исходного файла. Граница фиксации единственного результата и блокировка новой мутации до освобождения слота остаются общими с T1.1c. `cancelled_not_submitted` относится к отправке сообщения. Локаторы используют имеющийся retained bundle и отдельного message intent не создают. [Снимок T1.1c](../../crates/kilogram-first-dialog/src/operation.rs#L134)

## Матрица проверки реализации

| Сценарий | Критерий |
| --- | --- |
| Два свежих готовых Setup на loopback | Два owner экспортируют и импортируют файлы через терминальные команды. Проверить TTY-путь с пробелами и Unicode и JSONL. Обе стороны подтверждают оба слота через отдельный status. |
| Перезапуск получателя при поставленном в очередь сообщении | Новый instance и обмен новыми bundle через терминал восстанавливают связь. По прежнему request ID и истории подтверждена ровно одна доставленная запись. |
| Неверный peer, перепутанные контексты, просроченный или устаревший bundle, заменённый retained-файл | Отклонение до IPC там, где причина доказуема локально, с сохранением прежнего выбора и прогресса. При конфликте равной ревизии runtime отклоняет иные подписанные байты. Observer получает отказ для всех трёх операций. |
| Отмена экспорта и частичный импорт | Управляемые барьеры до записи и после публикации, после первого принятия и при потерянном ACK. Проверить кандидатный путь, один коррелированный итог, сохранение подтверждённого слота и идемпотентный retry сохранённого файла. |

## Уточнения приёмки

Сохранённый `Accepted` — историческое подтверждение конкретного digest. При отказе текущего runtime, включая уже применённую более новую ревизию, этот бит не повышает результат до `imported`. Отдельный `status` остаётся источником сведений об активном соединении.

Digest, копия и IPC используют один неизменяемый буфер. При retry повторное открытие после проверки исключается. Перед каждым IPC повторно проверяются подписи, срок и маршрут из этого буфера. После допуска записи или импорта возвращается последний доказуемый снимок, включая отказ второго слота. Пока сохранение выбора не подтверждено, `retained` равно `null`. Экспорт заносит кандидатный путь в снимок до допуска публикации и сохраняет режим no-clobber.
