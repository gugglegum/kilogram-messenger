# T1.3. Восстановление связи знакомых собеседников в LAN

Проект для review. База `e2d899c85b0f5eebeca67952daf8c41b3dd18e0d`. Один ранее согласованный собеседник, два текущих контекста, fresh Ordered Dialog 2, Windows IPv4 LAN. После открытия сохранённых профилей или краткого обрыва оба узла сами находят актуальные сокеты и проходят прежний admission. Пользователь видит состояние соединения и может читать историю и ставить сообщения в очередь в пределах текущего согласия. T1.2e подтвердил Direct LAN, ручной обмен локаторами и доставку после штатного перезапуска получателя при выключенном Private Firewall. [Результат T1.2e](terminal-t1-2e-readiness.md)

**Одновременный перезапуск.** Старые локаторы могут оставаться подписанными и действительными по времени, но оба endpoint ID и сокета уже от прежних запусков. Даже получив новый IP:port как подсказку, A пока не знает новый TLS endpoint с доверенной подписью, а у B `route_for_remote` отклонит новый endpoint A. Оба узла должны получить актуальные подписанные локаторы **до** первого OD2 admission. Cache и повтор старого адреса полезны только пока адрес действительно обслуживает тот же endpoint.

## Выбранный транспорт и граница сети

Оба `Owner2` независимо от OD2-роли периодически передают пару текущих `RuntimeLocator2`, зашифрованную для ранее согласованного Device. Место встречи — IPv4 multicast `239.255.75.72:50372`, TTL 1. Это отдельный канал от history recovery (`239.255.75.71:45371)). A пробует обычный OD2 после локального импорта. Если B ещё не принял пару A, listener отвергает попытку, следующая разрешена по backoff. Дополнительного ACK готовности нет. Сообщения и история идут по прежнему Iroh, сокет обнаружения существует только при работающем владельце.

Opt-in только для fresh Direct LAN, выключен по умолчанию. При включении терминал сообщает, что другие устройства в LAN смогут заметить периодические объявления. Разрешены **прежние точные local/peer IPv4**, заранее выбранный GUID адаптера, активный NLM Network ID в категории Private и фактический IPv4-префикс. CIDR подтверждает on-link, точные IP остаются обязательными. Потеря исходной привязки закрывает сеть, после возврата всех исходных параметров запускается новое сетевое поколение. Изменение IP, адаптера, Network ID, префикса или категории требует явной перенастройки для работы с изменившимся набором. Краткое отсутствие сети при открытии профиля или конфликт порта сохраняют локальные IPC, историю и очередь в рамках согласия. Меняются endpoint ID и UDP-порт при rebind на **тот же** local IPv4. Автоматическая смена IP/DHCP, Интернет/NAT и другие контакты вынесены за рамки. Ручной режим сохраняет прежние настройки и поведение. [Точные IP в DirectLan2](../../crates/kilogram-protocol/src/ordered_dialog_v2/runtime_locator.rs#L7) · [Текущий статус IPC](../../crates/kilogram-runtime-ipc/src/ordered2.rs#L355)

Windows-привязку при включении и в цикле проверки раз в 2 с формируют из актуального списка адаптеров/assigned IPv4/prefix/ifIndex и однозначного активного `INetworkConnection` по `GetAdapterId`. `GetNetworkId` и `GetCategory` читаются из его `INetwork`. Перед отправкой объявления, открытием gate и новым OD2 admission сверить текущую привязку. Смена или потеря привязки отменяет поколение. Join и egress задают выбранный интерфейс. `WSARecvMsg/IP_PKTINFO` подтверждают входной ifIndex и адрес назначения группы, источник обязан совпасть с точным peer IPv4 и IP обоих подписанных локаторов. TTL и область multicast ограничивают распространение, доверие проверяют подписи и policy. Ошибка bind, options, packet info или неоднозначность привязки блокирует discovery без подстановки интерфейса, порта или слабого fallback. Первый Windows-срез проверяет точную привязку и нативное получение ifIndex до интеграции с Owner2. ## Wire v1 и срок объявления

Канонический CBOR с definite-length массивами, минимальным кодированием и исчерпанием входа. `B = [1, issued_at, expires_at, [[consent_ref_0, locator_0], [consent_ref_1, locator_1]]]`. Время — Unix seconds `u64`. Consent refs — bstr32. Локаторы — исходные бинарные `ParsedRuntimeLocator2` в bstr до 244 байт каждый, ровно один IPv4:UDP без relay. Упорядочить записи лексикографически по байтам подписанного context ID (строгое возрастание), затем сопоставить два ожидаемых context ID локальным слотам. Локатор содержит ссылки на сертификаты обеих сторон, account/device/cert берутся из текущих установленных credentials. Сертификаты целиком в кадр не входят.

`S = [B, bstr64(signature)]`. Подпись Ed25519 установленного отправителя над ASCII `kg:od2:lan-discovery-sign:v1\0` (конечный NUL) и следующими за ним каноническими байтами CBOR(B). Шифруется ровно 704 байта `u16be(len(CBOR(S))) || CBOR(S) || zero-padding`. Декодер проверяет длину и нулевое заполнение. HPKE Base использует уже имеющиеся X25519/HKDF-SHA256/ChaCha20Poly1305 и закреплённый ключ шифрования получателя, со свежей инкапсуляцией для каждой отправки. ASCII info `kg:od2:lan-discovery-hpke:v1\0`. AAD — CBOR `[bstr(ASCII "kg:od2:lan-discovery-aad:v1\0"), 1, bstr4(group_ipv4), 50372]`. Внешний пакет — CBOR `[1, bstr32(encap), bstr720(ciphertext)]`. Другой размер, версия или wire отклоняются. [Ключи Owner2](../../apps/kilogram-cli/src/ordered_dialog/runtime2/owner.rs#L177) · [Подпись с тегом](../../crates/kilogram-protocol/src/ordered_dialog_v1.rs#L200)

Бюджет в байтах. Локатор максимум `1 + (1 + 1 + 4×34 + 11 + 1 + 3×9) + 66 = 244`: четыре ID, один IPv4 с портом, null relay, три `u64` и подпись. `B ≤ 1 + 1 + 2×9 + 1 + 2×(1 + 34 + 2 + 244) = 583`. `S ≤ 1 + 583 + 66 = 650`. С префиксом длины получается до 652 байт, остаются минимум 52 байта нулевого заполнения. HPKE tag добавляет 16 байт к 704. С 32-байтовой инкапсуляцией и CBOR обёрткой получается ровно `1 + 1 + 34 + 3 + 720 = 759` байт UDP payload. Во всех четырёх публичных bundles T1.2e оба локатора имеют по 228 байт. С типичными 32-битовыми Unix timestamps образец `S` с префиксом занимает 612 байт. Без сжатия и фрагментации, первая проверка подтверждает допустимый MTU для 759 + IPv4/UDP. [Формат локатора](../../crates/kilogram-protocol/src/ordered_dialog_v2/runtime_locator.rs) · [Публичный пример](../../.tmp/terminal-t1-2e/t12e02/b-locator-1.json)

Перед импортом проверяются подписи, обе authority/consent, scopes, интервалы и сохранённый wall high-water. `issued_at ≤ now < expires_at`, `0 < expires_at - issued_at ≤ 60 s`, весь интервал внутри срока обоих локаторов и согласия. Локальное сетевое поколение говорит, когда пакет получен и принят, а время его создания заявлено подписанным кадром. Replay в оставшемся окне может лишь вернуть подсказку того же подписанного сокета. Доказательство актуального peer даёт обычный OD2 admission. После импорта срок пригодности цели задают сами локаторы, policy и сетевое поколение, срок здоровой lease — прежний минимум locator/consent/lease. Истечение 60-секундного окна объявления само по себе здоровую lease не прерывает.

В LAN видны IP/MAC, версия и multicast endpoint, размер и периодичность кадров, факт присутствия и последующий трафик OD2. Снаружи отсутствуют стабильные прикладные IDs. HPKE скрывает account/device/context/consent и подписанный сокет в payload, фактический UDP OD2 всё равно виден по заголовкам последующего трафика. Долговременный ключ получателя при компрометации позволяет открыть записанные объявления для этого ключа. Журналы содержат причины и счётчики без пакетов и ключей.

## Допуск пары и повтор

- В `Owner2` единственный gate `Option<Pair>` в памяти. При старте он закрыт, независимо от БД. В открытом состоянии он содержит локальное network generation и endpoint, policy generation, точный peer endpoint/сокет и по два context ID, locator hash/revision и consent ref. Перед изменением проверить оба слота, общий endpoint/socket, policy и поколение. Нижняя ревизия и равная с другими байтами отклоняются. Перед **первым изменяющим** commit закрыть gate и инвалидировать старые lease/попытки. Выполнить прежние два `RuntimeOperation::Locator`, затем заново прочитать сохранённые байты обоих слотов и проверить соответствие пары, актуальной policy и поколения. Только после этого открыть gate. Частичный commit оставляет gate закрытым и сохраняет достигнутый high-water. Повтор с теми же точными локаторами может закончить второй слот. Точный повтор уже открытой пары обходится без записей и без инвалидирования lease.
- Opt-in gate проверяют выбор цели dial, входной фильтр listener, `route_for_remote` после TLS, `begin_admission` и все дальнейшие раунды, включая `observe_hello_authority` до раннего изменения authority. `Lease2::check`, peer commit и выдача `live_admitted` тоже требуют совпадения пары и поколения. При закрытом gate OD2 отклоняет admission и peer commit и показывает `live=false`. Старые callback отбрасываются по generation и fingerprint. Per-slot `ImportLocator`, терминальные `locator_import/locator_retry` доступны в ручном режиме. Opt-in отвергает их с указанием явно выбрать ручной профиль, локальный экспорт остаётся диагностикой. Межслотовая транзакция БД не требуется. [Import](../../apps/kilogram-cli/src/ordered_dialog/runtime2/owner.rs#L869) · [Admission](../../apps/kilogram-cli/src/ordered_dialog/runtime2/admission.rs#L55) · [Хранилище](../../crates/kilogram-state/src/vault/indexed_dialog/runtime2_ops.rs#L598)
- Fingerprint цели формируют точные байты обоих локаторов (их hashes), сопоставленные с упорядоченными контекстами и сетевым поколением. Новые timestamps, подпись обёртки и HPKE инкапсуляция цели не меняют. Допустимой цели после отказа разрешены повторы по таймеру с backoff 0,5–15 с и jitter. Дубликаты не сбрасывают backoff, отклонённые кадры не продлевают пригодность цели. Новая пара или восстановление разрешённой сети будят цикл досрочно. Одна попытка на контекст, до двух активных dial/listener соединений суммарно, admission deadline 30 с. Одна очередь discovery до 4 датаграмм, до 8 проверок/с на владельца, bounded drop при заполнении, без ответов на входящий пакет. Под постоянным flood гарантируется верхняя граница ресурсов, доступность peer не гарантируется. Объявление с jitter раз в 2–5 с в поиске и примерно раз в 15 с при соединении.
- Владелец показывает «локально готов», «поиск адреса», «повтор/аутентификация», «подключено» и причины сетевой или policy-блокировки. «Подключено» требует двух текущих Active2/lease. История, ввод и постановка в очередь проходят обычным локальным путём в рамках текущего согласия. Сетевые ожидания идут вне обработчика команд и транзакций БД. При `quit` остановить задачи обнаружения и подключения, закрыть discovery/Iroh, дождаться принадлежащих владельцу задач и снять IPC-дескриптор.

## Проверки и последовательность

| Проверка | Критерий |
| --- | --- |
| Focused: wire и scope | Синтетические ключи и часы. Размер и padding, формат, wrong peer/cert/context, IP и ifIndex, срок, нижняя и конфликтующая ревизия, wall rollback. Replay в окне проходит только как подсказка, новый wrapper старой пары не сбрасывает таймер. Окно объявления истекает без отключения здоровой lease. Ошибка TLS/Hello сохраняет `live=false`. |
| Focused: пара, сеть и ресурсы | Ошибка второго commit и restart между слотами сохраняют закрытый gate. Admission и изменение authority в промежутке, прямой per-slot IPC и late callback отвергаются. Точный повтор заканчивает пару. Проверить открытие без сети, возврат тех же параметров, смену IP/профиля и конфликт порта. Одновременный dial, дубликаты и flood соблюдают caps/backoff, ввод и история работают, quit закрывает сокеты, задачи и IPC. |
| Один физический сценарий | Два Windows-хоста, одноразовые согласованные профили, исходные точные IP, принятый host/mailbox. Соединение → один restart с очередью и новым портом → оба restart с доказанно недоступными старыми сокетами и новыми endpoint ID → краткий обрыв и возврат. Без переноса locator-файлов. До 90 с от локальной готовности обеих сторон на разрешённой сети до обеих live lease. Проверить реальные и подписанные сокеты, ревизии, тот же request/event ID, точную историю и уведомления, отсутствие потерь и дублей, exit/EOF/пустые Jobs. |
| Включённый Windows Firewall | Для стабильного пути EXE владельца нужны узкие входящие UDP-правила Private + выбранный InterfaceAlias + точный peer IP. Discovery — группа `239.255.75.72` и порт 50372. OD2 — назначенный local IPv4 и фактический динамический диапазон UDP либо более узкий тестовый набор. При ограничении outbound разрешить этот multicast endpoint и прямой UDP между двумя адресами. Проверить effective policy, выбранный интерфейс и edge traversal Block. 1. Закрепить opt-in и codec. Сдать wire-тесты и **нативную Windows feasibility** (типизированный NLM для точной привязки, join/egress и входной packet info, MTU, конфликт порта, fail closed). Сохранить ручной путь. Только затем интеграция Owner2.
2. Подключить gate, импорт, статусы и retry к действующим OD2/IPC. Сдать focused частичный commit, оба restart на управляемых адресах, отсутствие доверия одному обнаружению и cleanup.
3. Выполнить один физический сценарий с включённым Private Firewall. Сборки Windows Idle, один Cargo worker, сетевые Rust harnesses через stable runner, существующий host/mailbox. [Порядок проверок](../verification-workflow.md)

Первый срез зависит от точного NLM/ifIndex и работоспособности отдельных multicast group/port на Windows. При неоднозначности API или сети локальные операции доступны, автоматический путь остаётся заблокирован до решения.
