## Activation and bounded records

The harness enables diagnostics only **after real Setup and its terminal owner have completed**, before Chat is started. Creating a foreign marker before begin/join would violate the existing empty-directory guard; that guard is preserved. `lab-diagnostic-enable` requires the bound active attempt, an existing plain setup.json, no IPC descriptor and a fresh diagnostic directory. It creates `setup/lab-diagnostics-v1/enabled.json` with strict schema1 and the attempt's32-hex generation. An invalid/missing marker disables diagnostics. Existing normal runs do not create this marker.

The shared sink accepts no arbitrary destination; it checks plain ancestors/reparse points,256-byte strict marker, generation, public64-hex runtime instance and finite directory count. Each record is CreateNew, at most16KiB, one fixed kind/PID name; errors never change application decisions. Production sites pass only fixed booleans/counters/static enums/public identifiers, not error strings, plaintext, recovery words, keys, frames or stderr. Host collection rejects unknown keys/string values/names, excessive depth/count/size, generation mismatch and known Chat/runtime PID/instance mismatch. Python checks content hashes and identity again. Collection coverage explicitly lists missing/rejected files. Runtime capture cannot be attributed if no complete PID/instance observation was obtained; it remains incomplete.

## Deadline and cleanup behavior

Admission starts before the two connect commands. One immutable report contains phase, monotonic start/cutoff/decision, raw exception type/message/timeout and raw-byte hashes, bounded rounds and the last complete runtime sample for each host. Runtime-connect failure is a distinct phase. No new host/observer/mailbox subprocess starts with less than2s. Each paired observation has a separate24s maximum and no more than48 rounds. It may finish after the90s cutoff; only runtime observations timestamped strictly before the cutoff can pass, and an observation exceeding its own budget cannot pass. Partial samples never combine across rounds into a successful pair.

On failure, one separate diagnostic snapshot is labelled after_deadline or after_failure and never evaluated for admission. Every observation, including this snapshot and shutdown collection, is bounded by the existing controller end that already subtracts60s from the native attempt work clock. Insufficient budget is reported; no additional time is taken from that reserve. Existing owner close, native cancel/end/wait and original-bin restoration still run on failure. Application, capture, native cleanup and restoration errors are preserved independently. No arbitrary shutdown timeout is raised.
