# T1.2e. Готовность полевого набора

База `8f82143bc6e92fd35342e82b91188f51f5e8146c`. Адаптер использует прежние Windows Job и pinned SSH/SFTP T1.1f. В режиме Setup launch перенаправляет все дочерние потоки с момента старта. Мост выдаёт только ограниченные проекции известных JSONL-ответов. `recovery_show` выполняется внутри хоста, а контроллер запрашивает только локальную имитацию сохранения слов. Буфер исходных байтов очищается. Строки в управляемой памяти имеют обычный жизненный цикл. От аккаунтов без состояния получены public pins, обменены invite/reply/proposal/final, подтверждены два локальных импорта и сохранены маршруты. Оба процесса штатно закрылись. При отсутствии уведомления драйвер сохраняет доставку и историю отдельной квитанцией и оставляет B неполным. [Целевые тесты](../../scripts/test-terminal-t1-2e-notifications.py)

## Предпосылки и запуск

Снимок перед запуском подтвердил оба хоста и прежний pinned SSH. Wi‑Fi ПК `192.168.0.140/24` напрямую подтверждён как Private при общей маске Private и Public. На ноутбуке назначен Wi‑Fi `192.168.0.152/24`. Запрос категории этого интерфейса не вернул значения. Косвенное свидетельство Private — единственная активная маска `0x2`. Private firewall отключён на обоих. Диапазон UDP заново прочитан как `49152–65535`. [Снимок перед запуском](../../.tmp/terminal-t1-2e/preflight-before-a.json)

После явного разрешения на передачу скриптов набор `t12e01` развёрнут по прежним стабильным путям на обоих хостах. Архивы `archive-t12e01` сохранены рядом с `bin`. SHA-256 обоих EXE D.2, `host.ps1`, `setup-pipe.cs` и существующего `deadline.ps1` подтверждены на двух хостах. Первое чтение полного снимка ноутбука истекло через 16 секунд. Короткая проверка подтвердила SSH с закреплённым ключом за 0,875 секунды, а повтор полного чтения с лимитом 36 секунд прошёл. ## Попытка `t12e01`

Оба Setup запустились. ПК создал тестовый аккаунт и передал ноутбуку приглашение размером 1861 байт с проверкой SHA-256. Ноутбук не ответил на `invite_inspect` за 55 секунд. Контроллер завершился через 105,828 секунды с кодом 1 до начала chat. Этапы A и B остаются открытыми. Локальный Job убрал дочерние процессы. На ноутбуке контроллер не получил Job-квитанцию. После проверки PID 4204 по пути тестового EXE и времени запуска оставшийся Setup завершён отдельно. Контрольное чтение показало ноль процессов `kilogram-*` и отсутствие IPC-дескриптора попытки. [Результат](../../.tmp/terminal-t1-2e/t12e01/result.json) · [Локальный Job](../../.tmp/terminal-t1-2e/t12e01/pc-setup-job.json) · [Удалённая уборка](../../.tmp/terminal-t1-2e/field01-remote-cleanup-and-stdin02.json)

Потеря ввода после паузы воспроизводится отдельной командой Windows PowerShell через закреплённый SSH без запуска Setup. Два байта, отправленные сразу, прочитаны. Первая строка после 3, 6 или 12 секунд не прочитана в пределах проверки. При немедленной первой строке и паузе 18 секунд вторая строка не прочитана. Keepalive с интервалом 1 секунда и периодические пробелы во входном потоке не восстановили получение строк. [Сырые байты и строки](../../.tmp/terminal-t1-2e/field01-remote-stdin03.json) · [Ранняя отправка](../../.tmp/terminal-t1-2e/field01-remote-stdin04.json) · [Keepalive](../../.tmp/terminal-t1-2e/field01-remote-stdin05.json)

Установленный Git for Windows OpenSSH воспроизвёл те же результаты на том же адресе при сохранении пина. Простой повтор полного сценария оставляет ту же зависимость от запаздывающего ввода. Для архитектурной проверки предлагается сохранить один Setup Job на хосте и доставлять только разрешённые команды и отфильтрованные ответы короткими закреплёнными SSH-запросами. Этот вариант требует отдельной проверки таймаута, очистки и сериализации запросов. [Сравнение клиентов](../../.tmp/terminal-t1-2e/field01-remote-stdin06.json)

Кандидат с короткими SSH-запросами прошёл локальную и удалённую проверки на имитаторе и принят для полевого A/B. [Транспорт](terminal-t1-2e-mailbox.md) · [Манифест](../../.tmp/terminal-t1-2e/mailbox04-review.json) · [Приёмка транспорта](../../.tmp/terminal-t1-2e/mailbox04-root-review.json)

## Полевой прогон `t12e02`

На обоих хостах прежний набор сохранён в `archive-t12e02`. По прежним путям установлены принятые `host.ps1` и `mailbox.cs`. Сверены все шесть файлов реального набора, включая оба EXE D.2, прежние `setup-pipe.cs` и `deadline.ps1`. Предпроверка и контроль после прогона подтвердили закреплённый SSH, прежние Wi-Fi адреса `/24`, диапазон UDP `49152–65535`, отсутствие процессов Kilogram и отключённый Private Firewall. Прогон относится к этой действующей политике. При включённом Private Firewall квалификация остаётся открытой. [Установка на ПК](../../.tmp/terminal-t1-2e/t12e02-pc-install.json) · [Установка на ноутбуке](../../.tmp/terminal-t1-2e/t12e02-laptop-install.json) · [Перед запуском](../../.tmp/terminal-t1-2e/t12e02-before-a.json) · [После запуска](../../.tmp/terminal-t1-2e/t12e02-after.json)

- **A прошёл.** Два свежих Setup подтвердили public account/device другого узла, один invitation ID, два контекста, согласие в обоих слотах и зеркальные LAN-маршруты. После импорта локаторов оба chat owner подтвердили `live_admitted` и `watching` в двух контекстах. Наблюдаемые UDP-сокеты совпали с обоими подписанными локаторами каждого узла. Из пустой истории доставлено по одному сообщению в каждом направлении. Сохранены два доставленных события, два точных уведомления и совпадающие строки истории. [Setup](../../.tmp/terminal-t1-2e/t12e02/setup-complete.json) · [Квитанция A](../../.tmp/terminal-t1-2e/t12e02/phase-a.json)
- **B прошёл.** Владелец на ноутбуке штатно закрылся до отправки третьего сообщения. Запрос на ПК был в `materialized` до запуска нового instance ноутбука. После обмена свежими локаторами запрос доставился, а `retry` по исходному ID вернул тот же event ID. UDP-порт ноутбука вырос с `63508` до `63513`, ревизии обоих локаторов с `1` до `2`. Итоговая история содержит одни и те же три строки на обоих узлах. Все три сообщения дали ровно по одному `incoming` с ожидаемыми контекстом, instance и epoch. [Офлайн-очередь](../../.tmp/terminal-t1-2e/t12e02/offline-pending.json) · [Доставка и retry](../../.tmp/terminal-t1-2e/t12e02/phase-b-delivery.json) · [Квитанция B](../../.tmp/terminal-t1-2e/t12e02/phase-b.json)
- Два Setup и три chat owner закрылись штатно. Все пять квитанций подтверждают `quit`, exit 0, EOF, принадлежность к Windows Job, пустой Job и отсутствие IPC-дескрипторов. Контроллер завершил A/B за 438,375 с. Резерв времени и исходные пределы контракта сохранены.
