## Зачётный прогон

`pilot03` завершился с кодом 0 за 365,078 с. В протоколе шесть уникальных request ID и шесть уникальных event ID. Для каждого получено ровно одно `incoming` с ожидаемыми контекстом, instance, epoch и текстом. На каждом хосте итоговая история содержит по три строки в каждом контексте. ID, текст, роль и ordinal по обе стороны совпали. [Полевой протокол](../../.tmp/terminal-t1-1f/pilot03/pilot.json) · [Код и длительность](../../.tmp/terminal-t1-1f/pilot03-ctl/driver-result.json)

- Четыре начальных сообщения прошли в обоих направлениях по двум контекстам. Обе стороны подтвердили `live_admitted` и `watching` до отправок. Квитанции Job зафиксировали UDP-порты ПК `62744 → 53139` и ноутбука `63220 → 63225`. В каждом поколении локаторы экспортированы и импортированы через terminal.
- После остановки владельца на ноутбуке пятое сообщение сохранилось на ПК в состоянии `materialized`. Ноутбук перезапустился, получил новый runtime instance и принял это сообщение один раз после свежего обмена локаторами. После перезапуска ПК `request_status` и `retry` с прежним request ID вернули тот же delivered event ID. [Офлайн-запрос](../../.tmp/terminal-t1-1f/pilot03/offline-request.json)
- Observer подключился к точному instance ноутбука и штатно отключился. Его Job завершился, а IPC-дескриптор владельца оставался доступным. Владелец получил шестое сообщение в том же instance и epoch. После `quit` у владельцев проверены коды child и wrapper 0, EOF обоих потоков и пустые Windows Jobs. Все 12 квитанций процессов подтвердили владение Job без принудительной уборки. Оба IPC-дескриптора исчезли. [Observer Job](../../.tmp/terminal-t1-1f/pilot03/laptop-laptop-observer-job.json) · [Postflight](../../.tmp/terminal-t1-1f/pilot03-ctl/postflight.json)

## Предыдущие попытки

- `pilot01` остановлен до доставки и запуска. Проверка ошибочно требовала единственный активный Private профиль на ПК. На ПК активны Private и Public на разных интерфейсах. Драйвер подготовки повторно проверил конкретный LAN-интерфейс, который действительно использует Private. [Исходная квитанция](../../.tmp/terminal-t1-1f/pilot01-ctl/preflight.json)
- `pilot02` доставил пять сообщений и записал пять уведомлений, включая сообщение из очереди после перезапуска ноутбука. Драйвер затем ожидал готовности монитора перезапущенного отправителя до обмена свежими локаторами и исчерпал этот таймер. Оба Job пусты, IPC-дескрипторы удалены. В зачётной попытке отправитель сначала выполняет обмен локаторами, затем оба терминала подтверждают `live_admitted` и `watching` до проверки `request_status` и `retry`. Для перезапущенного получателя очередь по-прежнему выпускается только после готовности его монитора. Исходники продукта не менялись.
